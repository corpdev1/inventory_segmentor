Issues :

  • Activator should exit if it cannot start properly. In this case, it could not recover the list of activated topics, so it should exit if something wrong happens.

Results:

  • After disconnecting the container's network, checking metadata before getting the list of topics is blocking for ~230 seconds, and returns an error, and abort the task to check for new topics. Tries again just after because of the ticker chan.
  • Checking inactive topics create goroutines for each topics to check (limited in the number available), but they are completely stuck, checking for partitions. I waited at least 10 minutes.

Code review :

  • The initialisation can get stuck if another instance of the activator runs on an active broker. Recovering activated topics waits for a new message on the activator output, and for each message recovered, the recovering timeout timer is reset to 20 seconds again.
  • Signals are not handled, closing the activator can have goroutines leaks.
  • Kafka Producers for "metric-activator" and "log-activator" are not closed when closing activator
  • There is no fallback when sending a message to an "-activator" topic fails. If a topic is detected and considered as active, but could not been sent to Kafka, the topic will never be activated unless the activator is restarted. We are currently only printing the error if the issue occurs.
    • We should add the topic in the inactivity list again if any error occurs while sending to the "-activator" topic
  • Main loop will not exit properly if the context is canceled, because it uses "break" instead of "return" when the signal is handled. (not an issue now since we are not closing properly the activator)

Related tasks :

    • Actually, if an error happens while producing a message, the topic is considerate as sent and will remain ignored.
  • Exit the program if the Kafka client cannot be created (currently segmentation fault) → DONE
  • Handle closure of activator (not a priority since we are containerising)
    • Handle termination signal
