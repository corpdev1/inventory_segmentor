Logical Components Orchestrator (LCO)

The goal of LCO is to register the wanted state on a logical component: to be monitored yes or no and propagate the wanted state to every host

LCO can be between the minima and techno service. It stores the desired states for each logical components.

  1. When a host starts on the infra. It registers it self to LCO. LCO acknowledge the new host on the infra. Default state for every logical component for the new is not monitored
  1. LCO compare the desired state witch each host's states. If it differents it build an activation or deactivation message and send it to kafka action topic (depends of the desired state) for each host.
  1. Hosts update their states on LOC

Scenario:

t0

  • Host A exists on infraID 1234 and X logical component is running
  • Host A register itself on LCO: X is not monitored on A
  • Minima activates the monitoring for logical component X
  • LCO stores the desired state: X have to be monitored
  • LCO compare the following statement: X is not monitored on A, X have to be monitored
  • LCO send activation message for X on host A
  • host A update its state on LOC

t1

  • X moves from host A to host B. Host B is not monitored by an agent for some reasons.
  • X disapears on the topology

t2

  • X move from host B to host C . Host C is monitored by an agent
  • Host C register itself on LCO: X is not monitored on C
  • LCO compared the following statements:
    • x is monitored on A (event if not present), x have to be monitored ⇒ Do Nothing
    • x is not monitored on C, x have to be monitored
  • LCO send activation message for x on host C
  • Host C update its state on LOC
  • x reappears on the topology

t3

  • Minima change configuration for the component X and want it to be monitored
  • LCO receives the desired state and stores it
  • If there was already a state for X
    • Compares the hash of the messages
      • if it is different it send action messages for every host registered
      • else it compares only the desired state vs hosts states and do actions according the result

t4

  • Minima deactivate monitoring for X
  • LCO stores the new desired state: X should not be monitored
  • LCO compares the following statements:
    • X is monitored on A , X should not be monitored ⇒ Do action
    • X is monitored on C , X should not be monitored ⇒ Do action
  • LCO send deactivation messages ton action topic for A and C
  • Host A update its state on LOC
  • Host C update its state on LOC
