Introduction

Logstash is the transform layer for Logs. It has several responsibilities like parsing logs, dropping fields, ....

Mainly, there are two main logstash services for logs :

  • Logstash FB : reads data from kafka after being collected by the agent with -raw suffix and send them to back to kafka with -stashed suffix after applying several transformations
  • Logstash ES : reads data from kafka after being collected by the agent and send them to Elasticsearch with prefix index- after applying several transformations

Logstash FB and Logstash ES

Overview

Logstash FB and Logstash ES are responsible for applying transformation to logs before it lands to Kafka and Elasticsearch respectiveley

  • Logstash FB : The goal is to prepare Logs as input for LAD
    • Non-kube: Read data from kafka that are collected by the agent and has suffix -raw
    • Kube: Read data from kafka that are collected by the agent and has suffix -raw and prefix ml.
    • Applying several transformation on logs
    • Send data to kafka after replacing the -raw suffix by -stashed suffix
  • Logstash ES: The goal is to prepare Logs as input for MELK
    • Non-Kube : Read data from kafka that are collected by the agent and has suffix -raw
    • Kube : Read data from kafka that are collected by the agent from the topic infraID-log-kubernetes-raw
    • Applying several transformation on logs
    • None-Kube: Send data to Elasticsearch with prefix index-
    • Kube: Send data to Elasticsearch with prefix index- and suffix yyyy-mm-dd

For more details, see the following diagrams.

For kube environment, a router is used in order to split the infraID-log-kubernetes-raw into several ml. -raw topics. The router has the ability to request metadata from Kubernetes cluster to get infos like the namespace, workload type and workload name

Logs transformation

Logstash FB and Logstash ES main responsibility is to apply transformations on logs :

The are general transformations, including:

  • Drop empty messages
  • Parse json messages and send them to jmsg field
  • Remove unused fields

Also there are groks, which are regexes that parse logs to several fields. The goal is to obtain mainly :

  • loglevel : used to know the level of logs
  • content : used by LAD as input for ML algos

The fields that are obtained from groks are assigned to the field grok_parsed_msg

For some Groks, we define custom patterns which are patterns that are defined by the user

Mapping loglevel fields to standard logseverity field. The are 4 main logseverity :

  • info : info, inf, information
  • warning: warn, warning
  • error : error, erro, critical, fatal
  • other : if no loglevel or not able to parse loglevel or not able to map loglevel

Deployment

Image creations

  1. Ensure you are on updated dev branch
    git checkout dev
git fetch
git merge origin/dev
  1. Tag the lad version with the commit hash
    # if tag with latest commit 
git tag v<major>.<minor>.<patch>-logstash HEAD

# if tag with specific commit
git log --oneline # and copy the the hash of the commit
git tag v<major>.<minor>.<patch>-logstash <hash>
  1. Push the tag to the remote. This will start a github action that creates the logstash docker image
    git push --tags

    N.B. Check that a docker image has been pushed with the corresponding tag to ECR . Note that images are created for all logstash apps ( fb, mb, es, ...)

Deploying to client

For each client/cluster, run the steps below:

  1. Go to https://github.com/PacketAI/code/actions/workflows/deploy-logstash-tags.yml. Click Run workflow, choose the tag, and input flux branch (affluences, zerogachis, etc) then click Run workflow
  1. Update the client deployment page accordingly.

Deploying groks to client

  1. Connect to the admin dashboard for the client you want to deploy groks
  1. After selecting the Groks panel, click on Edit for the component where you want to deploy groks
  1. Write groks on the grok panel or copy paster from User submitted groks

Deploying new custom pattern

Custom patterns are stored in this file and used by Logstash FB and logstash ES

In order to add new custom pattern, use this format :

CUSTOM_FORMAT_NAME %{PATTERN1}%{PATTERN2}

and redploy logstash

Deploying new mapping of logseverity

Add new mapping to logseverity needs to be modified in the following files for logstash-fb and logstash-es

Simply in the translate field, you need follow this format if you want to map warn to warning:

"warning" => "warn"
