ACLs

Documentation: https://docs.confluent.io/platform/current/kafka/authorization.html

  • AclAuthorizer stores kafka acl in zookeeper
    • server.properties should have
      authorizer.class.name=kafka.security.authorizer.AclAuthorizer
  • ZooKeeper has its own ACL
  • Clients are principals
  • AclAuthorizer only supports individial users
  • Best practice: create one principal per application
    • and grant permissions on exact topics each application needs
  • Best practice: run with one principle per application
  • ACL identifies operations which users or group authorized to perform (List of operations https://docs.confluent.io/platform/current/kafka/authorization.html#operations)
  • ACL identifies which users can access resources (eg create a topic etc)

Quotas:

Protect againt client DOS (denial of service) other clients and broker themselves (eg kafka not responding?)

Allow to enforce API limits.

  • enforced on request
  • control (each) broker resources used by clients

Two types of quotas:

  • Network bandwidth (byte rate thresholds)
    • on a per-broker basis
  • Request rate - CPU utilization threshold = % of network and I/O threads

How quotas are applied:

  • can be applied to tuple (user, client-id) (where client-id is logical grouping, user is authenticated principal)
  • can be applied to client-id groups

For a given connection most specific quote matching is applied.

Order of precedence for quota configuration is:

  1. /config/users/<user>/clients/<client-id>
  1. /config/users/<user>/clients/<default>
  1. /config/users/<user>
  1. /config/users/<default>/clients/<client-id>
  1. /config/users/<default>/clients/<default>
  1. /config/users/<default>
  1. /config/clients/<client-id>
  1. /config/clients/<default>
