Design: data migration from single tenant to multi tenant

MongoDB

  • mongodb dump the documents from single tenant, and import them(mongo restore) them to multitenant Mongodb.
    • We need to consider the scenario where Mongodb document id's match with existing docuemnt ids on multitenant during the restore.
    • This collision should be bare minium, if not we could get list of document ids from each collection and check the corresponding collection for matching.
    • we need to prepare some scripts to alter the document id incase if there is collision
    • Mongo restore won't update documents if there is matching document id. so won't alter the existing documents. https://www.mongodb.com/community/forums/t/how-to-avoid-duplicate-id-error-during-restoring-collections-using-mongorestore/6225/2

Postgresql

  • for moving data from single tenant to multitenant, we could postgresql dump and restore. check here: https://www.mongodb.com/community/forums/t/how-to-avoid-duplicate-id-error-during-restoring-collections-using-mongorestore/6225/2
  • Should prepare scenarios where there might be duplicates when restoring the postgresql
    • before restoring make sure you don't have any conflicts on multi tenant postgreSQL db.

Elasticsearch

  • We could start restoring last 14 days of data from Single tenant S3 backup.
  • which could kind of slow but less error prone
  • Once all the DB's (PostgreSQL, Mongodb) moved we could ask client to use new Multi tenant website, and start updating packetai agents.
    • If we use HTTPs based endpoints then we don't need client to do anything, we might simply ask him to use new multi tenant website, we could configure route53 dns records to point single tenant URL's to Multitenant API's. So it's kind of seamless migration

Kafka

  • There is no need to move data from S-Kafka (single tenant) M-Kafka (Multi tenant). Since we are using Kafka as streaming messages, we let user to move to multi tenant

S3 Bucket

  • if the S-S3 bucket and M-S3 bucket are different then, we need to move ML prediction data to M-S3. this way single tenant user can use the existing prediction models on Multi tenant environment without waiting for delay
  • https://aws.amazon.com/premiumsupport/knowledge-center/move-objects-s3-bucket/
    • we could copy directly all the files between s3 buckets, we could use this to migrate ML and raw backups if needed.
