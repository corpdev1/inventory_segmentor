The Sandbox is a version of Minima that has a custom login which captures emails and uses a tour library to show scenarios of using PacketAI.

The tour step components are made with the reactour library.

Sandbox login (Accounts):

To make Minima use the demo login which captures emails the ACCOUNTS_VERSION env needs to be set to demo.

A DEMO_ACCOUNT_USERNAME env also needs to be set up with the actual account that will be used to show the sandbox demo.

After the user submits his email, Accounts will log him in as the DEMO_ACCOUNT_USERNAME and store his email on Becky.

If the user wants to use the regular login he can do so by selecting it from the screen:

Tour scenarios (Minima):

The above mentioned DEMO_ACCOUNT_USERNAME needs to have the demo_user role set in MongodDB(regular and openID) in order for the sandbox tour to be activated.

The main tour component is the one that is use to show the buttons to select the tour scenarios which takes the user to the appropriate page and sets the tour page accordingly.

An example would be the Installation tour scenario link which takes the user to the deployment page and shows the INSTALLATION_TOUR_AGENT_PAGE step.

Every scenario has steps defined here, naming is done so that the steps has the page which it uses in the name.

Every page then has a tour component that is shown if the current step targets that page. For example the topology page which is shown if the current tour step is OVERVIEW_TOUR_TOPOLOGY_PAGE .

There are also 2 incident scenarios and the overview scenario incident that require links to existing incidents which are set as env variables.

Becky data retention exclusion:

Since Becky has a scheduler that deletes old data it needs to be restricted not to delete the incidents which are used in the tour scenarios and their indices. These are also set as env variables.

Minima and Becky restrictions:

Since the demo user account has a pre setup infrastructure that should not be changed(for example user cannot activate/deactivate different integrations) there are restrictions on the UI and the routes to disable these interactions:

  • Minima check if the user is demo and disables some actions(example on Alerting page) and changes the agent instructions.
  • Becky has a restriction to important routes with a middleware that checks if the user is the demo user and does not allow access.
