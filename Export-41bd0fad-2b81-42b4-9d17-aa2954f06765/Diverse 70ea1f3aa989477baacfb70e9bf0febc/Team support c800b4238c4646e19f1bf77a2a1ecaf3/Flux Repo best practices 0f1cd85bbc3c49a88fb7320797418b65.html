1. Deploy New Service to single cluster

  1. We need to identify where this service belongs
    1. check if it needs to part of ML(base/ml/) or MS(base/ms/) or logstash (base/common/logstash/)
  1. create new folder inside appropriate base folder for the micro service.
    1. create k8s deployments or statefulsets or ingress or services based on what you need.
    1. make sure you create kustomization.yaml file inside this folder.
  1. Goto cluster folder and modify the kustomization.yaml at the root of the cluster folder.
    1. add the new folder under the resource section
    1. ex
    apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../base/common
  - ../base/ms
  - ../base/ml
  - ../base/ml/NEW_FOLDER
  - config
  - secrets

    Example:

    Let say we want to add new logstash service called pubsub to deploy only talentsia cluster.

    1. WE need to identify the location for this service, we could this under base/common/logstash folder
    1. let's create logstash-pubsub folder under base/common/logstash
      1. create k8s controllers resources and add kustomization.yaml file under this folder
    1. Let's go to talentsia-cluster folder
      1. edit kustomization.yaml file located under the cluster folder.
      apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../base/common
  - ../base/ms
  - ../base/ml
  - ../base/common/logstash/logstash-pubsub
  - config
  - secrets

2. Deploy New Service to all clusters

  1. We need to identify where this service belongs
    1. check if it needs to part of ML(base/ml/) or MS(base/ms/) or logstash (base/common/logstash/)
  1. create new folder inside appropriate base folder for the micro-service.
    1. create k8s deployments or statefulsets or ingress or services based on what you need.
    1. make sure you create kustomization.yaml file inside this folder.
  1. Go to parent of the current micro service. There should be kustomization.yaml, add this folder path to this file under the resources section.

    Example:

    Let say we want to add new logstash service called pubsub to deploy to all clusters.

    1. WE need to identify the location for this service, we could this under base/common/logstash folder
    1. let's create logstash-pubsub folder under base/common/logstash
      1. create k8s controllers resources and add kustomization.yaml file under this folder
    1. Let's edit base/common/logstash/kustomization.yaml file and add the logstash-pubsub to resources section like below
      namespace: "logstash"
resources:
- namespace.yaml
- logstash-aws
- logstash-cw
- logstash-es
- logstash-fb
- logstash-mb
- logstash-minima
- logstash-template-indexer
- logstash-config-loader
- logstash-pubsub
    1. That's all, this new resource will deploy to all the clusters, nothing to do more

3. Deploy New Service to all clusters except few clients

  1. First we need to identify and deploy the new service to all the clusters as in scenario 2.
  1. We need to scale down the new service in particular cluster
    1. Goto cluster kustomization.yaml file, add below code under patchesJson6902: section
    1. examples:
     # ml-sire scale down to zero pods
 - target:
      group: apps
      version: v1
      kind: Deployment
      name: ml-sire #( here your service that's scaling down, if it's deployment)
      namespace: argo-events
    patch: |-
      - op: replace
        path: /spec/replicas
        value: 0

  #postgresql scaledown to zero pods
  - target:
      group: apps
      version: v1
      kind: StatefulSet
      name: postgres-postgresql #( here your service that's scaling down, if it's statefulset)
      namespace: postgres
    patch: |-
      - op: replace
        path: /spec/replicas
        value: 0

Examples:

Let's say we want to scale down the logstash-pubsub service to talentsia cluster, but like to deploy to all the other clusters.

1) We will deploy the logstash-pubsub as described here

2) to scale down this service for talentsia cluster we just need to edit talentsia-cluster/kustomization.yaml file

 # ml-sire scale down to zero pods
 - target:
      group: apps
      version: v1
      kind: Deployment
      name: logstash-pubsub
      namespace: logstash
    patch: |-
      - op: replace
        path: /spec/replicas
        value: 0

4. Update a new version of a MicroService to Single cluster

Generally It's good practice for kustomizing particular service for particular cluster, we need to add the modification in that cluster-folder (ex: talentsia-cluster, kpeek-cluster etc..).

We could the kustomization a particular service in 2 ways.

1) patchesStrategicMerge

2) patchesJson6902

patchesStrategicMerge

In patchesStrategicMerge we could define the overlay config for a particular service. and add this config to patchesStrategicMerge section of cluster kustomization file.

examples:

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../base/common
  - ../base/ms
  - ../base/ml
  - ../base/ml/logpatterns
  - config
  - secrets
  - ../base/common/logstash/logstash-beat
  - ../base/ms/beats-ingester
patchesStrategicMerge:
  - overlay/compute-resource/opensearch.yaml
  - overlay/compute-resource/logstash.yaml

see logstash.yaml and opensearch.yaml

patchesJson6902

We could accomplish the same kustomizations using patchesJson6902 as patchesStrategicMerge .

Currently we are using patchesJson6902 to update replicas count, image tags etc…

To update a service to new version to particular cluster.

we need to add the following snippet under patchesJson6902 section of cluster kustomization.yaml file.

example:

- target:
      group: apps
      version: v1
      kind: Deployment
      name: logstash-pubsub
      namespace: logstash
    patch: |-
      - op: replace
        path: /spec/template/spec/containers/1/image
        value: 767498580550.dkr.ecr.eu-west-3.amazonaws.com/logstash-pubsub:v2.0.0-logstash-latest
