Upsert API

When saving the grok results, we will save filters together with the groks we define. e.g.

{
  "default_groks": [],
  "user_defined_groks": [
    "%{WORD:content}", 
    "%{GREEDYDATA:content}"
  ],
  "filters": {
		"field1": ["v1", "v2"],
    "field2": ["v3", "v4"],
  }
}

It means we generate groks for any log contains field1 with v1 or v2 &  field2 with v3 or v4. When we save the grok results into db, we save the same filters together instead of using fixed field topic.

When u update, u should match exactly the record with the exact values of each field in filters ($all operator)

"field1": ["v1", "v2"],
"field2": ["v3", "v4"],

GET API

When we want to fetch the groks, we would send again the filters, but this time the matching logic is different from the updating logic.

e.g.

{
  "field1": ["v1", "v8"],
  "field2": ["v3", "v10"],
}

The matching shall match any record contains field1 with v1 or v2 &  field2 with v3 or v4. Just like the matching logic when we query the logs.

e.g.

The get should match the record we saved in db with filters

"field1": ["v1", "v2"]
"field2": ["v3", "v4"],

or 

"field1": ["v8"]
"field2": ["v10"],
