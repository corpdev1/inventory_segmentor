Technology

  • Agent
    • Agent is written in Go and is a light-weight daemonset (k8s) or system script (non-k8s)
    • For k8s, agent is deployed as a Helm chart. Agent auto-updates when Helm chart is updated
    • There are 2 agents : cluster agent that sees all nodes, node agent that sees 1 node
    • Agent is responsible for (1) mapping topology, (2) extracting logs and metrics
    • Agent sends its data to a Kafka endpoint on the client
  • Topology (see this article)
    • PAI does only physical topology, and this is rendered in the Topology Tab of the UI
    • Physical topology
      • It describe parenthood relationship, eg: deployment / pod / container (k8s) or host / application / service / process (non-k8s)
      • Classification of processes into application/service/process is based on open tcp connexions traced via system kernel
    • Virtual (or logical) topology
      • How 2 metrics, eg mongoDB CPU metric and python app CPU metric are correlated.
      • PAI has done a POC on this but this is not GA
  • MAD (see MAD page for more info)
    • MAD stands for Metric Anomaly Detection
    • How does MAD work ? MAD is an online anomaly detection algorithm that is composed of multiple outlier detection algos fitted with noise suppression. It auto-learns during a warmup period and can then detect anomalies on metrics.
    • What are the exact steps ?
      1. baseline a metric (observing it for 3 days to get seasonality)
      1. classifying its shape (some shapes are flat, linear trend, sparse, etc.)
      1. applying a shape-specific deviation detector to said metric
    • What are important metrics ? A list of metrics (that we choose) that can trigger anomalies. Metrics not in that list cannot trigger anomalies.
    • How are important metrics chosen ? It is a choice based on domain knowledge
    • Where does MAD write to ? MAD writes (1) anomaly scores to Kafka.mlmetrics which goes to ES, (2) Anomaly regions to ES, (3) Anomalies to MongoDB .
  • Anomalies and Incident management
    • Anomaly vs incident ?
      • An anomaly is a component metric or log abnormal deviation
      • An incident is a group of related anomalies
    • Can LAD and MAD trigger anomalies
      • Only MAD at the moment but LAD will in the short future
    • How are anomalies grouped into incidents ?
      • When an anomaly (occurring on an important KPI) is detected on a component, we search for the earliest anomaly on any of the other metrics of that component. This is the RCA anomaly. All other anomalies of that component from RCA to “now” are added to the group and form the incident. The grouping will also comprise related components that suffer anomalies on that same time period.
    • What is incident severity ?
      • Severity is either CRITICAL, WARNING or INFO. This label is computed by a hybrid rule-based / ML system called Incident Manager
      • Incident manager works by applying business rules (edicted internally) and if no business rule applies by applying ML model which is based on client feedback. Without client feedback (eg at beginning), business rules can still be applied
      • From anomalies, some features are extracted (duration, impact, etc.). Some of these features are used as inputs to business rules; some others as inputs to ML part.
  • LAD
    • LAD stands for Log Anomaly Detection
    • LAD comprises a set of algorithms that
      1. detect log velocity change
      1. detect sentiment (esp. negative) on certain log lines
      1. detect rare log lines
    • Log Patterns is not considered as being part of LAD (it is a descriptive not decisional feature)
    • How does LAD works ? LAD has a distributed topic processing architecture : A LAD client consumes an activator topic and is responsible for assigning a new topic to a LAD server (with minimum load). When receiving a new topic to process, a LAD server launches a new detection pipeline process
    • Other log anomalies that can be implemented in the future: https://medium.com/packet-ai/raw-logs-in-insights-out-log-analysis-with-packetai-4a6a2edd8591
  • Log Patterns
    • This algo groups log lines into clusters of similar log lines
    • It works line by line, by first masking (certain fields), tokenizing and clustering lines into different clusters
    • It is an online unsupervised algorithm that uses a fast n-ary tree to identify the cluster to which the incoming log line belongs to.
  • Data Pipeline
    • The data pipeline features a message-based architecture centered around Kafka. Each micro-service reads from and writes to Kafka. Some consumers are dedicated to writing data to ES or Mongo sinks.
    • Agent to pipeline : the agent continuously streams logs and metrics to Kafka. It also sends topology map.
    • For k8s,
      • a first pipeline sends all messages to ES, first traversing logstash to proceed with simple data transform and normalization, before ingestion into ES.
      • a second pipeline features a micro-service that routes each incoming message to a dedicated per-component Kafka topic. ML services consume those individual topics and apply models in real-time, writing output back to Kafka topics.
