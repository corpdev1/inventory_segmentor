PoC playbook

Requirements

  • to send data (example.jpg) to our s3 buckets, the client should use:

aws s3 cp example.jpg s3://our_bucket --acl bucket-owner-full-control

allowing us to have full control, including read, over the sent objects. (https://aws.amazon.com/premiumsupport/knowledge-center/s3-access-file-folder/)

  • in addition to that, in order to access the sent files, make them public (might have to change this)

PoCs go in five steps:

1. data evaluationdd

The goal of this step is to make sure we have the data necessary for the PoC. This step requires collaboration with the client, and full transparency from our side regarding the absolute requirement for data. "Our algorithms do not and will not work on bad data".

  1. check if all required data is present, tickets (if available) and raw data
  1. check for data breaks and missing data

  1. if tickets are received, make sure they exactly correspond to the time span of raw data
  1. if tickets are received, make sure they exactly correspond to the same IT environment as raw data.
  1. communicate to the client what part of the data is good and being used for the PoC before starting the PoC

Once all required data is present, move to step two.

2. data preparation

The goal of this step is to make sure we have data necessary for the PoC in an expected format. This step might require collaboration with the client. This step includes two sub-steps:

2.1. manual data cleaning

  1. for example, organise data in files and put them in specific paths when necessary
  1. do any other necessary manual action on data

    2.2. build the regex-es for Logstash Groks

  1. use this for pre-built regex https://github.com/logstash-plugins/logstash-patterns-core/tree/master/patterns
  1. else, use the grok debugger to build custom regex https://www.elastic.co/guide/en/kibana/current/xpack-grokdebugger.html

3. run Packet algorithms

  1. run log frequency AD algorithms, with time windows: 1min, 5min, 10min, 15min, 30min

    TODO if few data points, use few-data AD algos, else, use big-data AD algos

    TODO if data is sparse, use sparse-data AD algos, else, use dense-data AD algos

  1. run event frequency AD algorithms, with time windows: 1min, 5min, 10min, 15min, 30min
  1. run Drain then LogCluster, with time windows: 1min, 5min, 10min, 15min, 30min
  1. do a visual correlation between tickets and anomalies
  1. save results in excel + dashboards. Example bellow:

4. analyse data visually to spot anomalies

  1. visually analyse data for abnormal patterns in frequency, with time windows: 1min, 5min, 10min, 15min, 30min
  1. visually analyse data for abnormal patterns in text, with time windows: 1min, 5min, 10min, 15min, 30min
  1. save results in excel + dashboards

5. compare results of steps 3 and 4

  1. use results and learnings from from 4 to improve algos if necessary
  1. communicate results to the client
