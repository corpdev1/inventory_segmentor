In the service stop monitoring file (suivie arrêt service) there is 3 anomalies :

  • 17/02/2020 on PARTOUCHE at 9:33
    • After plotting, the data looks like that between 9am and 10am. Which is in average smaller than 50
    • However, in average, between 9am and 10am there is 120 logs on average computed on the whole data
  • 19/02/2020 on APF at 12h14
    • Number of loglines dropped to 0 between 12:00 and 13:00

  • 16/03/2020 on CTS at 9:21
    • The data shows no activity at this range of time. Normally the logs starts showing up at 5:50.

In summary, for jobcycle logs, the anomalies are clear for APF and CTS which stands for absence of logs during the declared periods.

But, detecting inactivity is obvious and straightforward. The need for an algorithm to detect this is an overkilling.

However, it would be very helpful if one could predicts those outcomes, i.e, discovering the anomaly before it happens.
