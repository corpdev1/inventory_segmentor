Incident manager / LogFreq 18.11.21

Story

  • Similar issue happened in the past
  • Context :
    • Refactoring of logfreq pipeline
    • New pipeline was started in test mode : data reception, ano detection, send to incident manager (then minima in incident page)
  • Symptoms :
    • no incident on the incident page seemed normal/expected (deliberate silencing)
  • When looking at mongo, looking for anomalies, no anomaly could be found
  • When unlocking anomaly sending, it revealed a high rate of anomalies that suddenly went live

Impact

  • Client impact : client could have seen anomalies which are not part of an incident

Root cause

  • Message format for ML anomalies topics has been changed without being reflected on the incident manager
  • Asynchronous nature of Kafka messaging deprives sender from feedback

Improvements

  • Document dependencies between ML and Eng (both ways)
  • Changes on ML or Eng team must include checking the dependency document and communicating with Eng or ML team
  • Establish release management on ML team : this is currently the only way to know which features are activated for a given client (and currently high complexity to have a switchboard to turn on/off features without redeployment)
