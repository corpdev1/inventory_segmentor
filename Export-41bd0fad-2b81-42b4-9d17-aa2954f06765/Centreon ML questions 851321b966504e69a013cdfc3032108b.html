Centreon ML questions

Some questions to address:

  • What are the steps required to choose which model to apply for each client?
    • MAD is a fully automated module and has the following major steps:
      • Warmup period of receiving client data and learning models (usually 3 days)
      • Detect anomalies with MAD algorithms (Skyline, Walter)
      • Perform noise reduction and assign relevance score for each anomaly
      • More details could be found here
    • LF: perform log count shape classification and construct deployment document which structure could be found here. The deployment document contains information about models that should be applied for the log level in question and which parameters should be chosen. It is sent to Mongo collection and consumed by LF module during inference. The architecture design could be found here.
      • Note: time to produce this deployment document is 5-10mn
    • LPA: client-oriented design (user decides which model to apply by choosing the detection type). We support 2 detection models (presence and drift). User must choose which model to use based on PacketAI documentation. The architecture design could be found here
  • For each model to be deployed, what operations are done manually?
    • MAD: everything is automated
    • LF: log count shape classification, mongo deployment document preparation for each eligible log level. As mentioned above, the document structure could be found here. The deployment document contains information about models that should be applied for the log level in question and which parameters should be chosen.
    • LPA: everything is automated
  • Can we get read-only access to your backoffice tool that manages models?
    • We don’t have a backoffice tool to manage models as model deployment is fully automated using Argo
  • What differentiates Anodot from PackatAI's AD?
    • Anodot applies AD on business, finops and G&A metrics data. This is mostly low-frequency signals with low cardinality (low number of metrics).
    • PacketAI applies AD on infrastructure metrics and log data. This is high-frequency signals (heartbeat on metricbeat: 10s) with the well known problem of high cardinality.
  • In Pipeline 4 it is mentioned how difficult it is to analyze log sequences for parallel applications. Was a solution found?
    • This was not pursued as no need from clients.
    • Solution would be to use a trace ID
  • What is jessy?
    • Jessy is out-of-date project
  • Explain the role of Gale/Drain in case of a new log
    • Gale is out-of-date project
    • Drain is the AI (unsupervised, tree-based algorithm) that transforms a log to a compressed form by keeping static parts and removing dynamic parts
