LogNER

Introduction

This document explores the application of Named Entity Recognition (NER) on log messages to identify the structure of each log entry, including the timestamp, log level, and message content. By automating the extraction process, NER techniques provide a solution to the challenges associated with manual log parsing. The document discusses the significance of log analysis, various NER techniques and algorithms, steps involved in applying NER to log messages, practical implementation through a case study, benefits and limitations, and future directions in the field. Readers will gain a comprehensive understanding of how NER improves log analysis and system maintenance.

Data Labeling

First attempt : Automatic labeling

Prior to manual labeling, an attempt was made to apply an automatic labeling method following the steps outlined below:

  1. Manual Labeling of Examples: For each log format corresponding to a specific technology, one example was manually labeled to serve as a reference.
  1. Prompt Construction: A prompt was constructed using the labeled example log and its expected output. This prompt served as a template for automated labeling.
  1. Automated Labeling: The constructed prompt was applied to generate labels for 10 additional logs.

However, it was observed that this method performed well for log messages with simple structures. Unfortunately, for longer messages, the automatically generated labels proved to be completely inaccurate. Consequently, manual labeling was deemed necessary to ensure the accuracy and reliability of the labeled data.

Second Attempt: Manual labeling

Due to the unsuccessful results of automatic labeling, a manual labeling process was carried out, encompassing more than 700 examples. The labeling was facilitated using the labelstudio tool, which provides a versatile labeling environment for various tasks.

While manual labeling ensures higher accuracy, it is acknowledged that the process can be time-consuming and monotonous.

Training

The model checkpoint utilized for fine-tuning in this project was distilbert-base-uncased. The training process was facilitated using the Hugging Face Trainer API, which provides a convenient interface for training and evaluating models. To assess the model's ability to generalize, the preprocessed data was divided into distinct training and testing sets, ensuring the inclusion of log messages from various technologies in both sets. This split is crucial in evaluating the model's performance across different log contexts.

Below a summary of the configuration :

  • Model checkpoint : distilbert-base-uncased
  • Training API : AutoModelForTokenClassification from HuggingFace Trainer API
  • Epochs : 5
  • Train / Test split : 70% of technologies used for train, and the rest for test
  • Learning Rate: 2e-5

Conclusion

In conclusion, the application of Named Entity Recognition (NER) on log messages proves to be a successful approach in identifying the structure of logs by extracting timestamp, log level, and message content. The results obtained demonstrate the effectiveness of NER techniques in automating the log analysis process. However, it is important to note that further improvements in NER performance can be achieved by augmenting the training data with additional examples and carefully selecting the appropriate model architecture. While increasing the data size and choosing more complex models may yield better results, it is crucial to consider the trade-off between accuracy and model speed. Choosing excessively large models can lead to decreased performance and slower processing times. Therefore, striking a balance between model performance and computational efficiency is essential in practical implementation. Overall, NER offers a promising solution for log analysis, and with careful consideration of data and model selection, it can significantly enhance the accuracy and efficiency of log parsing tasks.
