Scaling profitably - cost analysis - WIP

Cost model

C_total=f(nbr_comp, traffic_in, retention) // these are the 3 sizing parameters

traffic_in=log_vol+metric_vol+topo_vol

C_total=C_kafka+C_MAD+C_LAD+C_log_patterns+C_ES+C_Logstash +C_other_MSs+C_data_transfer

C_kafka=C_kafka_G_6h*traffic_in // cost of 1G retained in kafka for 6h * traffic_in

C_MAD=f(nbr_comp, traffic_in) and C_LAD=f(nbr_comp, traffic_in)

C_MAD=C_MAD_comp*nbr_comp

C_LAD=C_LAD_comp*nbr_comp // so far, LAD is not really used though deployed

C_log_patterns=C_log_patterns_G*log_vol

We also note: C_ML_log=C_LAD+ C_log_patterns

C_ES=C_ES_G*(log_vol+metric_vol+residual) // residual=f(nbr_comp)=ml_indices …

Where

C_total is the total cost of a cluster

C_kafka is the cost of kafka C_kafka_G_6h is the cost of 1G retained in kafka for 6h

C_MAD is total cost of all MAD pods

C_LAD is total cost of all LAD pods

C_log_patterns is total cost of all log pattern pods

C_ES is cost of ES cluster

log_vol is the volume of received logs

metric_vol is the volume of received metrics

topo_vol is the volume of received topology data

Note

The breakdown of C_LAD and C_log_patterns will be done once LAD is broken down into different microservices

Notes

  • the architecture of a kube cluster is crucial to how it is billed. Clients should organise components as business entities to minimise costs. For eg, an organisation like Metron is not optimal cost-wise, where the number of pods exceeds 2k. Also creating a statefulset for each pod is not optimal.
  • we can think of a feature where users manually compose components from pods on the UI
