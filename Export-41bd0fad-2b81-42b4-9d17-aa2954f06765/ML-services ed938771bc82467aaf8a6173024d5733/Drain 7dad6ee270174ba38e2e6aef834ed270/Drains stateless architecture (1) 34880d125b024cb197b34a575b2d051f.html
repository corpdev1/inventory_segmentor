Drains stateless architecture (1)

  1. Drain structure

    Drain tree == dictionary :

    topic: {seqlen:

    {token: {token: {.. token: [log_template1, log_template2,..]}}}

    }

  1. Drain operations
    1. read if matched seq
    1. write or append if not matched seq

  1. for same one topic, only one batch of logs is allowed to send to drain gateway
  1. if one topic batch logs need write operation, write one total changement to database and its cache, then return `reload` signal back to drain gateway, drain gateway then broadcast to all pods
    1. how to make sure all pods are notified using broadcast?
      1. we can use label `latest_write_ts` for each topic in drain gateway, and attache it with the batch of logs sending to one pod, and verify with the one in drain pod, if drain pod topic latest_write_ts is earlier, then it need to update from DB(it is possible to only fetch the latest changement)
  1. in every pod, topic cache can only keep the most recent frequently used topics, if one log arrive and don’t find its topic, need to fetch from DB
  1. the drain pods are stateless service under one deployment, it is HPA
  1. try to make drain gateway send different topics to different pods through its deployment routing strategy(not sure if exist)
