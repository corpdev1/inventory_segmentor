Parallezation (1)

we can transform and represent drain tree into follow structure:

when tree deeplevel = 2:

topic1, token number, first_token : [log1_tokens, log2_tokens, log3_tokens, … ]

topic1, token number, first_token : [log5_tokens, log6_tokens, log7_tokens, … ]

topic1: [1,2,3]

topicé: [4,5,6]

topic1+topic2: [a,b,c]

topic1_log1: 1

topic1_log2: 2

topic1_log1: a

topic1_log2: b

topic1, token_number, nginx1:

topic1, token_number, nginx2:

topic2, token number, first_token : [log1_tokens, log2_tokens, log3_tokens, … ]

topic2, token number, first_token : [log5_tokens, log6_tokens, log7_tokens, … ]

….

content= “nginx down for one hour” ⇒ [ngix, down, for, one, hour]

drain tree operation:

given a new input log tokens

  1. search by token nb and first token, and find the log_tokens with highest similarity score > 0.51
  1. if not exist or best score < 0.51, insert the new log tokens into above struture
  1. if exist, replace common token by <*> for the log_tokens in above list

Improvement points

  1. today parallezation only happen at topic level, we can go further into token number, first token level,
  1. can store above structure in some in memory db
  1. similarity score calculation can be parallized across different log_tokens in the list
  1. input log distribution: many input log can be duplicated, there are also a lot of above operation can be duplicated
