Contributions

  • To the best of our knowledge, this paper is the first work to use sentiment analysis for identifying anomalous activities in OS logs. Detecting negative sentiments can be considered as a new way of detecting irregularities in OS logs.
  • We consider class imbalance in OS log data by applying the Tomek link method.
  • We build a GRU layer to detect sentiment analysis of log messages. This layer is built on top of the Tomek link method and a word embedding layer.
  • To enable reproducibility of this research, we provide the source code implementation of the proposed method, the preprocessed and labeled system log datasets, and the trained model on a GitHub repository.1 The model can be readily used to detect anomalous activities in an OS log file. Finally, we name the proposed method pylogsentiment.

Collective anomaly is when several data occur together as a collection and appear to be anomalous, while its individual instance may not be an anomaly. 4.1 Preprocessing of Operating System Logs

...

We use the nerlogparser [42] to parse system log files and extract the main message in each log entry. The nerlogparser tool is based on named entity recognition (NER), which is a process used to extract named entities from text. In log files, nerlogparser defines named entities as words or phrases containing common fields in a log entry such as timestamp, host name, or service name. The extraction of named entities is the equivalent of identifying each field in a log entry. The nerlogparser utilizes bidirectional long short-term memory networks to perform NER [42]. The main benefit of the nerlogparser is that it provides automatic parsing because it is completed with a pre-trained model. Therefore, we do not need to define any rules or regular expressions. It can parse various log files as the nerlogparser has been trained in diverse types of logs.

4.3 Solving Class Imbalance with the Tomek Link

...

We use the Tomek link [12] to create a new representation of the majority class by under-sampling. We chose this method because it removes the samples from the majority class based on the minimum distance. In OS log data, the majority class is often repetitive and can be considered as a noise. Therefore, we can remove several log data from the majority class without affecting the performance.

5.1 Operating System Log Datasets

To test pylogsentiment against different types of domains, we also use other public system logs. Zookeeper is a management system for distributed systems. The logs were acquired from 32 hosts at the CUHK (Chinese University of Hong Kong) laboratory for 26 days [48]. Hadoop is a big data tool that can distribute jobs across machines. The logs were generated in a Hadoop cluster with 46 cores across five machines [49]. The anomalous events are machine down and network disconnections. BlueGene/L is an open dataset from a BlueGene/L supercomputer at Lawrence Livermore National Laboratories (LLNL) with 131,072 processors and 32,768 GB memory. The log entries include alert and nonalert logs. The alert messages indicate anomalous activities.

The last three datasets are not included in the training phase. These datasets are for testing unknown anomalies, as discussed in Section 5.6. Spark is a management tool for big data processing. The logs were collected from 32 hosts where include both normal and anomalous activities from the Spark system [48]. Honey5 is from The Forensic Challenge 5 2010, The Honeynet Project [51]. The paper also provided a github link to the project that contains the developped idea called Pylogsentiment : https://github.com/studiawan/pylogsentiment

Two key ideas are behind build a sentiment analyser for logs :

  • Build a ground truth of logs that are labelled with negative or positive
  • Build an ML model based on this dataset

Build ground truth

The ground truth dataset is built in 2 steps :

  • Collect a list of logs from, mainly, linux systems
  • Collect a list of words that are known to be negative
  • Combine both

The list of logs is collected from here : https://github.com/studiawan/pylogsentiment/blob/master/datasets/README.md

It contains linux system logs that are taken from previous public challenges : casper-rw, dfrws-2009-jhuisi, dfrws-2009-nssal, honeynet-challenge-7, honeynet-challenge5

They are presented into a different list of files like : syslog, auth, messages

In the other hand, the project provides a list of words that are known to be negative for each type of log. For example, for auth logs :

The next step is to combine the logs and the words list in a way that create a training dataset for the machine learning. For this experiment :

  • Combined all the logs from the different sources
  • Clean the logs the same way as here
  • Combine all the words of different types
  • If one of words is present in a log, then this log is labelled as negaitve

The final dataset looks like above where 0 means negative log :

  • Number of logs : 1320
  • Number of negative logs : 183 (12%)

We are clearly in front of imbalanced dataset.

Train ML model

Using the created dataset, a model is built following 2 steps :

  • Encode the logs using Spacy large embedding. Using this technique helps to decrease overfitting to certain words, since the model will deal with vectors and not words
  • Build a Random Forest model on 80% of the data

After building the model, the f1-score on the remaining 20% of the data is computed.
