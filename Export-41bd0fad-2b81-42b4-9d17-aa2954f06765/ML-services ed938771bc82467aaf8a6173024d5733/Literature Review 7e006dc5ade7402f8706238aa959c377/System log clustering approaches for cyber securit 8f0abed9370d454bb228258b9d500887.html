Introduction

Why dealing with logs ?

  • Contains information about the events that happened on the system
  • Trace back the root for observed problems
  • Help to recover the system to a non faulty state
  • Validate the performance of process and discover bottlenecks
  • Storing the logs is not expensive

How to deal with logs ?

  • Proactive analysis by constantly monitoring on real-time manner
  • Follow indicator of erroneous
  • Data is immense and fast, we need machine learning to process the logs and discover interesting patterns
  • Clustering is the main ML approach for this problem

Background

Characteristic of log data

  • A logfile is a set of single or multiline string listed in chronological order
  • Could be highly structured (comma separated), semi-structured (key-values pair) and unstructured (free text)
  • PID (process ID) that describe the task are generally attached
  • Level of the log (INFO, DEBUG, ERROR, ...) to indicate the severity
  • Logs are not natural language because : Similar messages repeated over and over and the appearance of some messages are highly correlated

Static clustering

  • Clustering individual loglines by the similarity of their messages
  • Token based or Character based (More flexible but More expensive)
  • Order and correlation between messages is neglected
  • Is mostly about template extractions

Dynamic clustering

  • Sequence analysis of templates extracted from static clustering
  • Analyse of frequency, co-occurence and aggregation after time-window aggregation

Survey

4 types of anomalies discussed

Types of anomalies

  • Outlier : Single logline that do not match any of the existing template (static clustering)
  • Frequency anomaly : log events that appears unexpectedly frequent or rare
  • Correlation anomalies : log events that are expected to occur in pair of groups or events
  • Inter-arrival time anomalies : deviating time in intervals between log events
  • Sequence anomalies : missing or additional log events, deviating order in sequence

Categories

  • Overview and filtering : Filtering out logs that are repeating without added-value
  • Parsing and signature extraction : Automatic generation of log event template
  • Outlier detection : Dissimilar to all existing clusters (templates)
  • Group anomaly detection : Group sequences of log lines or disclose temporal patterns such as frequent co-occurrence or correlations are required.
    • Linking events to some task or process ID
    • Linking event through time-window aggregation

The article set many criteria to differentiate between the approaches and provided this website http://81.189.135.168/selection/ to compare between them

Other

Issues pointed by the paper

  • Template extraction : Overgeneralisation
    • Example 1: User A logs in with status -1
    • Example 2: Use B logs out with status 1
    • Template extraction : User * logs * with status *
    • logs in and logs out are two different things, however the template extraction merged them together
  • Merging logs with different Log Level is not recomended
