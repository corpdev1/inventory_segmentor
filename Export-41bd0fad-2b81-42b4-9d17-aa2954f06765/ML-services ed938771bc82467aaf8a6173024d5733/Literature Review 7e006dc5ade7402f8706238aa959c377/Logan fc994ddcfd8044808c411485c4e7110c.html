Logan

Summary:

The idea of Logan is to fix Drain issues:

  • Ability to match templates with different lengths. This avoids drain's "quick decision"
  • Improve Drain's implementation: storing templates in cache and parallel processing

Template Extraction Overview

High level steps:

  1. preprocess to extract obvious variables
  1. compare to existing templates
  1. if no match, add line as a new template in cache

Detailed steps:

1. Pre-processing

4 substeps:

a. Tokenization

b. We analyze these tokens to identify URLs and file paths using regular expressions.

c. process composed tokens: split each token on every non-alphanumeric character and replace all the decimal and hexadecimal numbers from the resulting tokens. This enables us to handle dates (“31/01/1997”), IP addresses (“127.0.0.1”) and other similar tokens without using specific regular expressions

d. discard weird tokens: We further replace all the tokens that contain at least one numeric character and less than three alphabetical characters. This preserves tokens like “HTTP505” while discarding tokens like “M20”. We observe that most meaningful tokens are shorter than 50 characters, hence, we remove all tokens longer than 50 characters.

A. Overview

B. Matching

Mostly statistical operations to pick a precise list of "normal" templates:

  • top 20 percent of templates will match 98% of log lines
  • less frequent templates but present in 80% jobs are also kept
  • using more lenient filtering constraints (this part is not very clear)

C. Frequency Filter and Feedback Loop

  • After training Logan on normal templates, it will output outliers.
  • if the outlier occurs more than "threshold" times, then remove it from output
  • threshold is fixed empirically
