The input files are as follows. They are prepared using RabbitMQ logs of Affluences. 40000 samples have been divided as 80% training, 10% development, 10% testing. This package doesn't accept IOBES format, only IOB. Internally it converts all inputs to IOB2 format.

The GloVe pre-embedding files were downloaded from here. 100d vectors were chosen based on the suggestion given here.

Here are the results for a training run, which ran SGD for around 7280 training samples (i.e., 7280 samples from the first epoch). Note: It took around 12 hours for this (training error was also computed at regular points in time, which is very time consuming). We see that the algorithm reaches 100% Precision and 100% Recall for dev and test sets after SGD with the first 480 training samples itself.

Note: There was noise in the tags for some cases when the test above was done.

In order to test the effectiveness of NER to deal with the presence of noise in the characters of the tokens, the following test was done. In the test data-set, the numbers were replaced by alphabets. This is an extreme level of noise in the date-time entity. Otherwise, the positions of the tokens were not changed. We see that the performance on the test set reaches a very good level, after some time, even in this case.

In order to check how sensitive NER is to the positions of the tokens, the following test was done. In the test set, the positions of the tokens were shuffled. Note: the date-time entity consists of two tokens and they were moved together. The content of the tokens were not modified. We see that the performance on the test set is much poorer compared to the above cases. The performance is slowly improving with more iterations of SGD.

From the above tests we can see that the algorithm is very much sensitive to the position of the entity with respect to the other entities. Thus, even if the content of the entity is noisy, it could still be recognized. However, we see much poorer performance when the positions of the tokens are shuffled.
