Peaks due to logstash aggregation

Data from Ruby component was analysed (6040a96cdcc614001153fc55-docker/rubylogs_fluentd/).

While analysing MAD data, we can see the following drop followed by a peak. Number of I/O operations during the life of the container was negative during June 7th around 13h30.

As for today (18.06.2021) the data flow looks as follows:

metricbeat data ⇒ Kafka raw topic ⇒ aggregation per 10S in logstash ⇒ Kafka stashed topic ⇒ aggregation per 60S in MAD ⇒ ML metrics Kafka topic

If we plot raw data which is coming from metricbeat we will see that during the 5 minute period when the peak in stashed data was observed raw values were not changing (the number of operations per each container was constant).

However, if we aggregate data based on @timestamp field by taking the average value over all values received during 10 seconds, we will observe that we do not have constant line as expected.

The following chart shows the distribution of raw data points per 10 second buckets for each docker container. We can see that for time bucket that corresponds to 13:27:00 - 13:27:10 period we received more points than usually (13 values instead of 8) and for the next time bucket between 13:27:10 and 13:27:20 we observed only 3 values (less than usually).

If we count the number of data points received per 10 seconds we will see that it is not uniformly distributed (sometimes we have more data points per 10 seconds, sometimes less) which results in spikes and drops in aggregated data.

Finally, in order to get the average number of I/O operations of docker containers per 10 seconds we apply diff operator to stashed data in MAD which results in negative drops followed by high positive spikes right after.

If we plot real data against the one we get after the aggregation in logstash we will observe discrepancy in data which results in False positives from MAD.

Possible solution(s)

1. Aggregate metric values over containerID within one time bucket and only after that aggregate resulting values (mean aggregation over time bucket of averaged values over containerID)

2. In case of incremental metrics: in logstash, wait until data for two time buckets is received, then for each containerID check if the average value is not missing for the first bucket. If it is the case: impute it with an average over contaierID, compute the average over previous time bucket and send it next to MAD.
