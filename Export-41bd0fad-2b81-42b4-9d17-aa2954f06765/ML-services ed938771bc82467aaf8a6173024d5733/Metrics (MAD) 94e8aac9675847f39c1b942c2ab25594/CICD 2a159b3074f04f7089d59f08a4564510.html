  1. CD solutions
    1. in house solution:

      a. topic dispatcher:

      topic-dispatcher client directly send new topic to one specific slave node

      b. blue green deployment:

      1. use aws commandline or sdk api to create new node based on MAD ami
      1. use codedeploy or ssh to deploy new code to the node
      1. once detect the service on new node is up, kill old node using commandline or sdk api

    1. solution using ELB and codeDeploy's blue green deployment

      a. blue green deployment solution:

      codedeploy support blue green deployment, it has dashboard ui support,

      we should verify if exist api to create new target group and create deployment group for the new target group

      https://docs.aws.amazon.com/codedeploy/latest/userguide/deployment-groups-create-cli.html

      and if possible if there is api to do the deployment instead of manual click on button for each deployment group

      b. topic dispatcher solution:

      codedeploy supported blue green deployment is by nature attached with a ELB, behind a ELB, there is a number of target group, each target group contains one slave node in our case.

      so our topic-dispatcher client get a target groupname(in which the slave node is least charged) from database, and put the target groupname inside of http header or url, and pass the http request with new topic to ELB. ELB listener get target groupname from http header or url, and forward to the target group based on some rule

      https://eu-west-3.console.aws.amazon.com/ec2/v2/home?region=eu-west-3#ELBRules:type=app;loadBalancerName=MAD-LB;loadBalancerId=a4a33c65aa8a4ae7;listenerId=6eac769ec98702c7

      need to check if exist api to add new target group in the rule

      https://docs.aws.amazon.com/cli/latest/reference/elbv2/modify-rule.html
