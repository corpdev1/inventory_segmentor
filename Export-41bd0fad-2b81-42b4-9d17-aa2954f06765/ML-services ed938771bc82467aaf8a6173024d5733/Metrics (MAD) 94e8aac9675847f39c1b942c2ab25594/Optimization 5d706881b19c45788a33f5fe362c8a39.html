First parallel processing proposition using different EC2 instance

Master orchester process

Listen to topic 'metrics_activator' in real time, and send new topic id to each slave node according to slave node’s health http report.(Maybe first several dozens of topics just use round robin,after that use health check)

Slave node process

Each topic process in slave get topic via http request, then consume the kafka data in the topic, do the preprocessing and instantiate the models in the slave node to generate prediction result and produce prediction to kafka, and we keep the accumulated window points (self.metric_values in code) in this slave node.

If long time no new data from the topic, then save the model parameter and accumulated window points self.metric_values to local disk or somewhere else, and then object.model=None, it will free memory. once there is new data, we reload the model and the self.metric_values to continue the process.

Parallelisation of detection routine based on univariate models

Problem: In the current implementation we are using univariate models for anomaly detection and apply it in a for-loop manner. This approach causes latency in producing results and needs to be parallelised.

One of the possible solutions would be using parallelized apply via pandas DataFrame.

Example:

def parallelize_dataframe(df, func, n_cores=4):
    df_split = np.array_split(df, n_cores)
    pool = Pool(n_cores)
    df = pd.concat(pool.map(func, df_split))
    pool.close()
    pool.join()
    return df

Here:

func could be any function which deals with pandas DataFrame

Other possible solution could be using pandarallel package

Usage:

With a simple use case with a pandas DataFrame df and a function to apply func, just replace the classic apply by parallel_apply .

How does it work under the hood?

When parallel_apply is called, Pandaral·lel:

  • instantiates a Pyarrow Plasma shared memory, then
  • creates one sub processes for each CPU, and asks each CPU to work on a sub part of the DataFrame, then
  • combine all the results in the parent process

The main advantage of using a shared memory compared to other inter-process communication medium is that there is no serialization/de-serialization which can be very CPU expansive.
