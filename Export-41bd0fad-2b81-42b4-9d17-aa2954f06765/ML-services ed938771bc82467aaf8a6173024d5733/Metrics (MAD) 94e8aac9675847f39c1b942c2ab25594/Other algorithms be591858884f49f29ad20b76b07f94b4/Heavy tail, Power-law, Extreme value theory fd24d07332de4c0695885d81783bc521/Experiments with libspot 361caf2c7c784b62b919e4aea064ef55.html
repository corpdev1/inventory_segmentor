As explained here: The main parameter is q. It defines the probability of an abnormal event. For example, if q = 0.001, it means that the algorithm will consider events with a probability lower than q as abnormal.

The parameters n_init and level are involved in the calibration step of the algorithm. n_init is the number of data required to calibrate and level is the proportion of these initial data not involved in the tail distribution fit. E.g., if n_init = 1000 and level = 0.99. The algorithm will drop the 990 lowest data and will keep the 10 highest to make a first fit.

Note: In practice, the user must ensure that n_init * (1 - level) > 10 to have enough data for the fit (at least 10). Furthermore, the level must be high enough to reduce the bias of the algorithm. We may advice to have the level as close to 1 as possible.

fit_mem is the maximum number of data stored to perform the tail fit. Note: If the memory is not bounded, the algorithm will store more and more data to perform the tail fit. However, the computation time will cause more problems than the memory growth because the tail fit complexity depends on this number of stored data.

  • As the algorithm progresses, the approach followed by libspot (refer algorithm 2 of the paper) is to consider only values that are greater than ttt﻿ and less than zqz_q zq​﻿ to adjust zqz_qzq​﻿. The samples that are greater than zqz_qzq​﻿ are marked as anomalies but are neither considered as an extreme value nor as part of the set of observations. This leads a quick drop in the value of zqz_qzq​﻿ as the algorithm progresses in a streaming manner. Refer equation 1 in section 3.3 of the paper. The number of observations nnn﻿ keeps increasing as long as normal and extreme values are encountered. However, NtN_tNt​﻿ increases only when extreme values which are not anomalies (i.e., values between ttt﻿ and zqz_qzq​﻿) are encountered. Thus, nnn﻿ grows much faster than NtN_tNt​﻿. zqz_qzq​﻿ is updated each time an extreme value is encountered and in practice zqz_qzq​﻿ reduces at too fast a pace, leading to many false positives at later times. Thus, a fix has been made to consider anomalous values also (i.e., all values greater than ttt﻿), to increment NtN_tNt​﻿ and nnn﻿.
    • Nevertheless, zqz_qzq​﻿ can decay at a quick rate after this fix also. Thus, when zqz_qzq​﻿ becomes lesser than ttt﻿, we use ttt﻿ (which is fixed at the initial calibration stage) as the threshold. This leads to situation where the algorithm starts using a fixed threshold for anomalies. It is better to always a have continuously adapting threshold for anomalies. Further thought is needed to dampen the effect of nnn﻿ increasing much faster than NtN_tNt​﻿.
    • One way to improve the situation is to re-calibrate ttt﻿ and zqz_qzq​﻿ regularly (say, once a month) based on one week of data. This needs to be tried.
  • In summary, these are the parameters that are used to tweak the thresholds:
    • The ratio threshold for vmax−vpvmax\frac{v_{max}-v_{p}}{v_{max}}vmax​vmax​−vp​​﻿.
    • The manner in which ttt﻿ is set based on the ratio.
    • The minimum number of extreme values expected in the calibration stage.
    • The maximum range of the synthetically generated extreme samples.

Observations

  • Initial calibration window of at least 1 week is preferable.
  • Regarding the memory parameter, we can see changes in the algorithm behavior when the value is varied in a low range (<200< 200<200﻿). Beyond a large value (>1440> 1440>1440﻿) there is no effect on the algorithm performance. Thus, a large value (1440, for now) is enough for this parameter.
  • This extreme value theory based approach is better suited for randomly varying time-series and also, sparse time-series (which requires further work).
  • When the data is sparse, even relatively small spikes are being classified as anomalies.
    • We can see an improvement in the experiment with sparse time-series where low values (values less than 5% of the maximum in the calibration period, which includes zeros) are filtered out. However, in very sparse cases there are no sufficient samples after this filtering step. An approach has to be tried that generates more number of significant samples based on existing significant samples of the calibration period.
  • Further work is needed to deal with the effect of number of observed samples increasing at a much faster pace compared to number of extreme values.
    • When a new extreme point is encountered after many observations then zqz_qzq​﻿ is updated to a lower value, this is mainly due to the form of equation 1 (section 3.3) of the paper. Maybe, it is also caused by how the GPD parameters γ\gammaγ﻿ and σ\sigmaσ﻿ are updated based on the extreme values (section 3.4). However, the update of the GPD parameters is based on the extreme values only and not affected by the number of observations.
