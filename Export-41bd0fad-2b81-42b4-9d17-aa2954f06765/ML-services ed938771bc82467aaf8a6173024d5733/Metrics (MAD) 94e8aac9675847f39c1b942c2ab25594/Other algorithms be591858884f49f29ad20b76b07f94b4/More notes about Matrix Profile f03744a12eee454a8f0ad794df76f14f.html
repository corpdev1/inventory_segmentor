More notes about Matrix Profile

@Hariprasad Kannan wrote:

Based on experiments on LogFrequency data, some more literature regarding Matrix Profile were studied. Here are some notes based on those studies.

The matrix profile consists of z-normalized Euclidean distance (and the index) to the nearest subsequence for a given subsequence, for all such subsequences. The pairs of the subsequences could be from the same or different time-series. The subsequences are determined by a subsequence length.

An important aspect for why Matrix Profile is gaining a lot of attention is the improvement of computational complexity from O(m.n2)O(m.n^2)O(m.n2)﻿ to O(n2)O(n^2)O(n2)﻿, where mmm﻿ is the length of the subsequences and nnn﻿ is the length of the time-series. For e.g., this article highlights this point. There has been a lot of work to gain further performance via parallelization and also, application specific performance optimization.

Computing z-normalized Euclidean distance between pairs of subsequences is a fundamental aspect of the Matrix Profile. The speed-ups are based on this aspect.

Matrix profile goes MAD: variable-length motif and discord discovery in data series, Linardi et al DMKD 2020

  • Algorithms to efficiently compute matrix profile in order to identify motifs and discords in a range of sub-sequence lengths.
  • Length based normalization in order to reliably compare and rank motifs/discords of different lengths.
  • Good intuition: Definition of top-k mth\text{m}^{\text{th}}mth﻿ discord (Figure 2, Definitions 8 and 9).
  • Exclusion zone to suppress false positives: I have misunderstood this concept. This exclusion zone is related to avoiding trivial matches while computing the Matrix Profile and it is already implemented by STUMPY.
  • The algorithms in this paper build upon an earlier algorithm called VALMOD. The following repositories implement VALMOD but it is not clear whether they have only implemented the motif part or the discord part also:

    https://helios2.mi.parisdescartes.fr/~mlinardi/VALMOD.html https://rdrr.io/github/franzbischoff/tsmp/man/valmod.html

The algorithms are not yet available in STUMPY as mentioned here.

MERLIN: Parameter-Free Discovery of Arbitrary Length Anomalies in Massive Time Series Archives, Nakamura et al ICDM 2020

  • Among anomaly detection techniques, discord detection has shown good results. However, it is limited by the correct choice of window length.
  • Points out curse of dimensionality when sub-sequence length becomes bigger. Oracle IoT articles also discuss this point (SAX for longer time-series and MP for shorter ones).
  • Mentions about z-normalization blowing up noise in small windows. Same point mentioned by "Eliminating Noise in the Matrix Profile".
  • According to them subsequence length of 3 is pathologically short for almost any domains.
    • According to MPdist paper, it makes sense to normalize time series till a minimum size of 3 and not lower.
  • Extends an earlier paper which presented a two stage approach to find discords based on a threshold parameter (minimum distance between subsequences). Note: The description of the two stages is better in the earlier paper.
    • The first stage identifies a bigger set of potential discords by comparing each subsequence with a growing set of discords (the set is initialized with the first subsequence). The second stage compares all the subsequences with this set of candidates and prunes false positives.
  • This paper presents an efficient way to search for the correct threshold parameter (by starting with a high value and slowly reducing it till it is enough).
  • Matlab code: https://sites.google.com/view/merlin-find-anomalies/
  • Lists many anomaly detection references: Detecting Spacecraft Anomalies Using LSTMs and Nonparametric Dynamic Thresholding, KDD 2018. 242 citations. https://github.com/khundman/telemanom

The Swiss army knife of time series data mining: ten useful things you can do with the matrix profile and ten lines of code, Zhu et al DMKD 2020

  • Paper proposes the use of Matrix Profile as a standard block of reasonable complexity that can be used by practitioners in various applications. Just like how sorting algorithms are used in various applications.
  • The ideas presented are instructive. However, they generally assume that the window size is known and also, other parameters of the application are known. The examples show that the matrix profile is useful but the information provided by matrix profile needs to be further analysed in a suitable manner, according to the application.
  • e.g. applications: Discovering motifs under uniform scaling (i.e., linear stretching or contraction) (assumes the scaling factor is known and window size), shapelet discovery (assumes shapelet length is known), time-series similarity using motifs (electricity meter readings) (assumes motif length is known), time-series clustering using minimum matrix pofile distance between pairs of time-series (assumes window size), segmenting repetive parts of a time-series by making use of the fact that matrix profile for the subsequences in the repetitive regimes will be low (assumes window size), discovering subsequences that flipped versions (either in time or in amplitude) of each other (assumes window size).

MPdist: A Novel Time Series Distance Measure to Allow Data Mining in More Challenging Scenarios, Gharghabi et al ICDM 2018

  • Longer time-series provide greater challenges to distance measures. (Also, mentioned by the swiss army knife paper.)
  • MPdist is claimed to be robust to spikes, dropouts, wandering baseline and missing values, and other issues. Not a metric but according to the paper it is an advantage.
  • MPdist is based on the idea that two time-series are similar if they have many similar subsequences. The locations of the subsequences don't matter thus providing robustness to phase change and also, capture higher semantic behavior.
  • MPdist between two time-series A and B: Compute MP of A w.r.t. B and B w.r.t. A. Consider the kthk^{\text{th}}kth﻿ smallest matrix profile distance as MPdist. Where kkk﻿ is 5%5\%5%﻿ of the sum of the lengths of the two time-series. This is more robust than looking at the maximum (vulnerable to spikes etc) or minimum (there will be similar subsequences between many pairs of long enough time-series) value. The extended paper discusses further about this choice.
    • We could take inspiration from this step and set a high threshold (since, we are looking for discord) and consider only cases larger than this threshold.
  • Even though the two time-series need not be of same length, the discussions seem to be based on same or comparable length time-series.
