Doubts

  • In our case ACF peak and dip happens after many samples. How to set p and q based on ACF and PACF when this happens?
    • A slowly decaying ACF indicates an AR process.
  • In our case, we have longer range dependency between samples. Do we need to take strided lags for AR and/or MA parameters?
    • https://stats.stackexchange.com/questions/294881/why-cant-arima-model-large-lags-and-or-long-range-dependence
    • There is a way to constraint the coefficient values. Using this strided lags can be implemented by setting inbetween coefficients to zero.
  • There seems to be a problem regarding "Frequency" parameter m used in seasonal model .

Validation criterion

  • Mean squared error. BIC. AIC. So far, we are using MSE, as described here.
  • AIC (Akaike information criterion): An estimator of out-of-sample prediction error. Lower AIC indicates a more predictive model. Check Pyramid-ARIMA below.

AR and MA parameter

  • Use ACF and PACF for AR and MA parameters.
    • Articles giving guidance: 1, 2, 3, 4.
    • General rules: An AR(k) process has a peak at lag k in its ACF, which decays in value slowly beyond k. An AR(k) process has a PACF that sharply goes to zero after lag k. An MA(k) process has ACF and PACF behaving the opposite way. Also, strong negative values in the ACF indicates an MA process.
    • Computing PACF is time-taking.
  • Beware of using multiple AR terms and multiple MA terms in the same model.
    • https://people.duke.edu/~rnau/arimrule.htm
    • What to do in cases like this?

The difference parameter

  • The difference parameters (d and D) are estimated and not found using grid search (https://stackoverflow.com/questions/56205579/pythonpmdarima-auto-arimapyramid-auto-arima-wont-use-d-and-d-args-automatic).
  • According to pmdarima (Pyramid ARIMA package) if d is None, the runtime could be significantly longer.
  • According to this article, difference parameters (d and D) have to be set in order to deal with periodicity.
  • The parameters d and q are related. d > 0 will usually mean setting q > 0.

"Frequency" parameter m used in seasonal model

  • Explanation about the parameter: https://robjhyndman.com/hyndsight/seasonal-periods/
  • There seems to be a problem regarding large valued m (it is 1440 for us): https://robjhyndman.com/hyndsight/longseasonality/
    • Update: This is the main cause for computational cost for us. One solution could be to model the seasonal part separately as a sum of Fourier terms and use only ARIMA for local prediction, as suggested in the above article.
