Pipeline (general description)[OUTDATED master-slave architecture]

  • Start listening to activator topic with master client →

    → once received a message with topic information launch a detection process by sending an http request to slave nodes

    • for each process:

      → for each topic initialize Skyline and Walter models →

      → extract and store a list of metric names from the first message →

      → for each message compose an input vector for our models and detect anomalies →

      → send results to Kafka to the topic with a corresponding name

Detailed description of the detection loop

To run the detection phase one should execute python3 activate_detection.py to start listening to the metric-activator topic. Once received a message with topic name, it will send an http request in order to launch a subprocess on the slave node via execution of the detection.py for particular topic.

What happens inside each process

We first initialize Kafka consumer, producer and a detector - an instance of a Detector class.

For each received message we:

  1. parse and extract a timestamp, infra_id, agent_id, component_id and an incoming_metrics_list (a list of dict, where in each dictionary an information about a particular metric is stored)

2. For the incoming_metrics_list we detect anomalies as described in Anomaly Detection section below

3. If detection output is None i.e. we had an error while detecting anomalies, we continue i.e. skip the message

4. Using the detection output we treat the output: compose a message for Kafka and a dictionary to store data in the csv format

5. We send results to Kafka topic with the name {infraID}-{agentID}-mlmetric-{componentID}-ml:

# send data to Kafka

Anomaly Detection

For the incoming_metrics_list we detect anomalies as follows:

  1. We first apply treat_input function which composes an input vector (self.compose_input_vector() function) and resets metric set (self.reset_metric_set() function) in case of unexpected input
    • The self.compose_input_vector() function checks if we received an expected input (self.check_incoming_metrics() function) and composes an input vector

2. If the input is accepted we store the input data and timestamp inside Detector's class as pandas DataFrame and array respectively (we keep only self.max_possible_data_points metric values records)

3. We apply Walter and Skyline models to get the anomaly scores

4. Once we have anomaly scores, we apply optimal weights to get the final score

5. Finally we compose and return an output dictionary:

out = {
    "metric_names": self.metric_names,
    "prediction": prediction,
    "score": averageScore,
    "metric_values": np.around(self.metric_values[-1], 5),
    "threshold": self.threshold,
}
return out

Optimal weights

In order to extract kafka topic the optimal weights one has to do the following:

  1. Checkout to feat-790/walter_skyline_profiling branch and run offline_detection_from_csv.py
  1. Run the mad_dashboard2.py from mad_evaluation folder and list all charts to store the corresponding tables
  1. Run Weight optimization.ipynb jupyter notebook from mad_evaluation folder to get the optimal weights
  1. Store this weights in the conf.py file as mad_weights dictionary
