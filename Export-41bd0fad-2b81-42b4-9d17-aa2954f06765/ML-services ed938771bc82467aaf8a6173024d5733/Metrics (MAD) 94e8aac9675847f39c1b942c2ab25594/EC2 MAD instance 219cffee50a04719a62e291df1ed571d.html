Launch MAD detection on the ec2 instance

Before launching MAD make sure you have cloned varloader project for certificates and kafka brokers setup.

While being in the metrics folder use one of these commands to declare Environment Variables:

  • dev: source ../varloader/mad/dev.sh
  • staging: source ../varloader/mad/staging.sh
  • prod: source ../varloader/mad/prod.sh
  1. Start MAD_dev_master and MAD_dev_slave ec2 instances
  1. Connect to the instances
  1. cd metrics/ (in both MAD_dev_master and MAD_dev_slave ec2 instances)
  1. Remove results/ folder (if exists): rm -r results/ (in both MAD_dev_master and MAD_dev_slave ec2 instances)
  1. Configure conf.py of the Master node: vim src/conf.py
    • Make sure you have worker's endpoints set up:
      1. In the Master node conf.py file check if you have indicated the localhost and slave's ip address in the WORKER_ENDPOINT variable. It should be looking like below: WORKER_ENDPOINT = ["http://localhost:8000", "http://ip-172-31-11-38:8000"]. (just to make sure, because slave has a fixed IP)
    • If you do an end-to-end:
      1. Set "detection_mode": "e2e" in the kafka_settings dictionary
      1. Specify the list of infraIDs you want to test for in the kafka_settings dictionary: "test_infra_id": ["5fad3548aadf2819b28da70c"],
    • If you want to run detection for one specific topic:
      1. Set "detection_mode": "test" in the kafka_settings dictionary
      1. Specify the topic name, agentID, infraID and the componentID you want to test for in the kafka_settings dictionary: 
      "test_topic": "5f7734a499aa8455e3b1f56a-5f77359999aa8455e3b1f56d-metric"
"-5a039db06d0c8d01-stashed",
"test_infra_id": "5f7734a499aa8455e3b1f56a",
"test_agent_id": "5f77359999aa8455e3b1f56d",
"test_component_id": "5a039db06d0c8d01",

    • If you want to launch detection for all topics contained in the metric_activator Kafka topic (be careful since one node can only process a limited amount of topics. For more details refer to this page):
      1. Set "detection_mode": "real" in the kafka_settings dictionary

  1. Enter tmux. Activate the virtual environement (in both MAD_dev_master and MAD_dev_slave ec2 instances): source venv/bin/activate
  1. Run gevent (in both MAD_dev_master and MAD_dev_slave ec2 instances): venv/bin/gunicorn pipelines.api:api -b 0.0.0.0:8000 --worker-class gevent --timeout 120 --workers=8
  1. Exit tmux from master crtl + b ⇒ d
  1. Run tmux again on master: source venv/bin/activate
  1. (Optional) To check the tmux instances use: tmux ls and to switch between the tmux instances use tmux attach -t 0 (or 1, or 2 etc)
  1. Run detection

    From the master node launch the appropriate command:

    • End-to-end:
      • Run from master node: python pipelines/activate_detection.py
    • Detection for one specific topic:
      • Run from master node: python pipelines/detection.py
    • Detection for all topics:
      • Run from master node: python pipelines/activate_detection.py

Setting up

Connect to current ec2 instance:

  1. Sign in to AWS in your browser. Go to EC2 instances and check whether the instance that you want to connect to is running.
  1. Go to the folder with AWS SSH key.
  1. Copy connect command from the browser for chosen EC2 instance. Example:

ssh -i "aws_id_instance.pem" ubuntu@ec2-35-180-29-236.eu-west-3.compute.amazonaws.com

Remember to change user from root to ubuntu.

Copy file from local to the ec2 instance:

scp -i "aws_id_instance.pem" -r path/to/file ubuntu@ec2-35-180-29-236.eu-west-3.compute.amazonaws.com:/home/ubuntu

Copy file from the ec2 instance to local:

scp -i "aws_id_instance.pem" -r ubuntu@ec2-35-180-29-236.eu-west-3.compute.amazonaws.com:/home/ubuntu/path/to/file destination/path/

Reset local git changes:

git reset --hard

Download MAD project from GitLab:

  1. SSH key
  1. Download master of your project: git clone https://gitlab.packetai.co/ex-machina/metrics.git
  1. Fetch all your branches if you need to run it

Setting up fresh-new ec2 instance:

  • use chmod 755 aws_paris_instance.pem or chmod 400 aws_paris_instance.pem for the SSH key
  1. Run the following command: sudo apt-get install python3 python-dev python3-dev \ build-essential libssl-dev libffi-dev \ libxml2-dev libxslt1-dev zlib1g-dev
  1. Install python-pip:

sudo apt-get install software-properties-common

sudo apt-add-repository universe

sudo apt-get update

sudo apt-get install python-pip

Install venv and all requirements

  1. sudo apt-get install python3-venv # install venv
  1. python3 -m venv venv # create a new virtual environment
  1. source venv/bin/activate # activate the virtual environment
  1. python -m pip install --upgrade pip # upgrade pip

Next, use these commands to install snappy. If not, you may have problems while installing snappy.

  • sudo apt-get install libsnappy-dev
  • sudo apt-get install python3 python-dev python3-dev \ build-essential libssl-dev libffi-dev \ libxml2-dev libxslt1-dev zlib1g-dev

From the MAD project folder:

  • pip install -r requirements.txt

Copy Kafka certificates to you project:

scp -i "ssh_key.pem" -r /path/to/file/on/local ubuntu@DNS:/home/ubuntu

Check stats of your instance:

df -h

Launch your script on the ec2 instance forever using tmux:

  • Connect to the ec2 instance and write the following commands:
$ sudo apt-get update; sudo apt-get install -y tmux
$ tmux
# Start your process
...
# Exit tmux: CTRL+b, then d
# Later, if you want to come back, connect to your EC2 instance and then:
$ tmux attach

Kill tmux session:

$ tmux ls
$ tmux kill-session -t id_of_your_session

Slave worker launch command:

pip install gevent

~/metrics$ venv/bin/gunicorn pipelines.api:api -b 0.0.0.0:8000 --worker-class gevent

(maybe also can add --timeout 120 and --workers=multiprocessing.cpu_count() * 2 + 1 --threads=threadnb)

Final command to launch:

~/metrics$ venv/bin/gunicorn pipelines.api:api -b 0.0.0.0:8000 --worker-class gevent --timeout 120 --workers=multiprocessing.cpu_count() - 1 --threads=threadnb

different server for gunicorn:

https://medium.com/@genchilu/brief-introduction-about-the-types-of-worker-in-gunicorn-and-respective-suitable-scenario-67b0c0e7bd62)

Master orchester launch command :

~/metrics$ python3 pipelines/activate_detection.py

In case of Gunicorn Connection in Use: ('0.0.0.0', 8000) problem use

sudo fuser -k 8000/tcp

Kubernetes cluster

Install and Set Up kubectl on Linux

  1. Download the latest release with the command:
    curl -LO "https://storage.googleapis.com/kubernetes-release/release/$(curl -s https://storage.googleapis.com/kubernetes-release/release/stable.txt)/bin/linux/amd64/kubectl"

    To download a specific version, replace the $(curl -s https://storage.googleapis.com/kubernetes-release/release/stable.txt) portion of the command with the specific version.

    For example, to download version v1.19.0 on Linux, type:

    curl -LO https://storage.googleapis.com/kubernetes-release/release/v1.19.0/bin/linux/amd64/kubectl
  1. Make the kubectl binary executable.
    chmod +x ./kubectl
  1. Move the binary in to your PATH.
    sudo mv ./kubectl /usr/local/bin/kubectl
  1. Test to ensure the version you installed is up-to-date:
    kubectl version --client

Create cluster

  1. Install docker and k3d:

    curl -s https://raw.githubusercontent.com/rancher/k3d/main/install.sh | bash

  1. Run local registry:

    sudo docker run -d --rm -p 5000:5000 --name registry registry:2

  1. Add registry.local to hosts:

    echo '127.0.0.1 registry.local' | sudo tee -a /etc/hosts

  1. Create cluster:

    sudo ./k3d.sh

Create Kafka

From ./k8s run the following command:

kubectl apply -k base/kubernetes-kafka/

Create Argo

From ./k8s run the following command:

kubectl apply -k base/argo

Create Argo Events

From ./k8s run the following command:

kubectl apply -k base/argo-events/

Deploy the EventBus

From ./k8s run the following command:

kubectl apply -n argo-events -f https://raw.githubusercontent.com/argoproj/argo-events/stable/examples/eventbus/native.yaml
