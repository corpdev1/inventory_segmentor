Copy of MAD pressure test on eks

Context

We create mad topics in Kafka and send metrics to these topics. Topics are dispatched on mad workers by two techniques:

1/ Argo workflow: For each new topic, it creates one mad pod.

2/ dispatcher/worker: The dispatcher sends the new topic to one existing worker. A monitor service monitors the state of the workers and create new worker if needed.

The objective is to measure the resources used by mad and decide which technique is suitable.

Commands

To specify in what nodes k8s starts the pods:

  1. Add a label to a node, e.g.

    kubectl label nodes <node names> app=mad

    (to remove: kubectl label node <nodename> app-)

  1. add nodeSelector to the pod spec configuration yaml spec.nodeSelector.app: mad
