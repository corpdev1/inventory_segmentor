Alerting Module client deployment

The following steps should be performed in order to deploy the AM:

Tag and creation of a new image

  1. Ensure you are on updated dev branch
    git checkout dev
git fetch
git merge origin/dev
  1. Tag the AM version with the commit hash
    # if tag with latest commit 
git tag v<major>.<minor>.<patch>-am HEAD

# if tag with specific commit
git log --oneline # and copy the the hash of the commit
git tag v<major>.<minor>.<patch>-am <hash>
  1. Push the tag to the remote. 
    git push --tags

    As for @May 12, 2022 we do not have a github action that creates the AM docker image, so you have to:

  1. Run the following script to build a docker image and send it to the ECR
aws ecr get-login-password --region eu-west-3 | docker login --username AWS --password-stdin 767498580550.dkr.ecr.eu-west-3.amazonaws.com
repo_url=767498580550.dkr.ecr.eu-west-3.amazonaws.com
tag=$tag
branch=$branch
git checkout $branch
image_tag_list=( alerting_manager:$tag )
docker_file_list=( am_Dockerfile )
cd $(pwd)/..
for index in ${!image_tag_list[@]}; do
    echo "build image for "${image_tag_list[index]}" on branch "$branch" from "${docker_file_list[index]}
    docker build -t $repo_url/${image_tag_list[index]} -f ${docker_file_list[index]} .
    echo "push image "${image_tag_list[index]}
    docker push $repo_url/${image_tag_list[index]}
done

N.B. Check that a docker image has been pushed with the corresponding tag to ECR

Manual deployment of the newly created image

  1. Switch to the target cluster k8s context
  1. Run
kubectl apply -f alerting_manager.yaml

Deployment via flux

  1. Add k8s manifest files for the alerting manager to the flux/{client}/ml/alerting_manager folder.
  1. Create flux/{client}/ml/alerting_manager/kustomization.yaml and add resources
  1. Add alerting_manager to the flux/{client}/ml/kustomization.yaml

Pipeline requirements to verify

  1. The am_rules Mongo collection is created and is filled with business rules
  1. The incident Minima collection is set to regular/ alpha mode (could be seen from the admin panel Settings → “Use regular/alpha incidents collection” is checked)
  1. The ml-alerting-manager deployment is scaled up in the argo-events namespace:
    1. Either regular or alpha docker image tag is used for the Alerting Module: the difference between the regular and alpha modes for the AM is that it listens to the regular/alpha issue mongo collection (could be set in code/ml/alerting_module/config.yaml, field issues_collection: issues or issues_collection: issuesalpha
  1. The incident-manager-deployment is scaled up in the packetai-system namespace
