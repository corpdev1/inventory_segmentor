LogFrequency Pipeline

@September 15, 2021

Following is the suggested pipeline to treat log counts data.

  1. The data classifier should run every x minutes to classify the data and to know the appropriate model to apply. Then it sends the output to a database ml:lad_logfrequency_models 
    {
   "topic":"613f0b9a49deb5157e6fcadf-linux615db09d59bf03006b93b748-log-linux615db09d59bf03006b93b748-stashed",
   "shape":"usually same value",
   "models":{
      "HB":{
         "max_bins":5, # number of bins 
         "alpha":0.5, # exponential weighted mean parameter
         "max_points":10080, # sliding window length in number of points 
         "warmup_period_in_number_of_points":10080, # warmup period in number of points
         "time_to_reset":10080 # model reset period in seconds 
				 "avg_level_alpha": 0.6, # exponential weighted mean parameter for the average level
         "avg_level_threshold": 10,  # average level threshold
      },
			"Skyline": {
			        "alpha": 0.7,
			        "median_absolute_deviation_threshold": 6,
			        "histogram_bins_min_points": 100,
			        "n_bins": 10,
			        "n_points": 5,
			        "max_history_time": int(60 * 60 * 24 * 7),
			        "threshold": 0.8,
			    },
   }
}
  1. LAD consumes the logs from the corresponding topic and checks the status of the topic in the database and updates the models list accordingly.

Notes :

  1. The classifier will run on 1-2 weeks of data to determine the right shape of the time series
  1. LAD will make 1 call to the database every 5 minutes to know the corresponding algorithms/parameters
  1. The classifier will read the backed-up mllog data from S3
  1. The used database is ml and the collection is lad_logfrequency_models
