Introduction

The following features are based on PoCs already done on correlation and causation.

The virutal topology graph

  • By clicking on topology, the user sees parenthood topology and dependency graph (connection-based topology)
  • dependency graph is computed using the graph layer of Weave scop (TBD)
  • parenthood topology + connection topology constitute the physical topology (black lines)
  • in addition to the physical topology, we provide a virutal toplogy based on algorithmic correlations
  • the virtual topology graph is constructed as follows:
    • nodes are physical nodes
    • two nodes A and B are connected if at least one SLI from node A is correlated to at least one SLI from node B
  • by clicking on a virtual edge, it expands to show underlying virtual connections (pairwise correlations of SLIs)
  • each virtual edge have a direction indicating causality relationship (undirected means absense of such causality)

Notes:

  • for kubernetes environments, replace weave scop by istio
  • see this section for highly dynamic environments

Leveraging the virtual topology in RCA

The correlation graph to be extracted from both physical and virtual topologies, as follows:

  • weights are attributed to each link type
    • 50% to parenthood link
    • 30% to connection link
    • 20% to a virtual link
  • a RCA connection is considered only if it has a score of ≥ 50%
  • the direction of an RCA connection is either determined by a causation link if any, else by time order

The what-if analysis page

Based on physical and virtual correlations, a what-if analysis is possible by indicating expected outcomes of supposed events. For example: the user can simulate peak on cpu on pod1 and the tool would indicate the following outcomes: peak on memory on pod1, peak of latency on pod2 and peak of latency on pod3.
