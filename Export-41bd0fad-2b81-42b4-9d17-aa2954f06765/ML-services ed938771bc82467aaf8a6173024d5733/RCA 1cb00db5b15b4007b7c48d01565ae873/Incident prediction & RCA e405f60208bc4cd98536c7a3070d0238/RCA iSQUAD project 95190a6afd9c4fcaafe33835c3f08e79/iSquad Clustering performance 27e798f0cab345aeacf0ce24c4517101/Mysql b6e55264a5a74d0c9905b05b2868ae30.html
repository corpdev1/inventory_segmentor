Conclusion:

Best performance is around 62%. Detailed cluster below.

Main counter-performance is grouping cpu and memory saturation in the same cluster.

Two explanation:

  1. cpus and mem saturation have quite similar impact on metrics. e.g. Drop in buffer pools metrics
  1. Topic algorithm is not completely deterministic. For each permutation of the input, it gives a different output and the quality of the clusters changes a lot. It keeps one pattern for a cluster. This pattern is chosen by the number of incidents in the cluster. For some permutations, cpu and mem are not completely grouped in the same cluster.

Improvements over the isquad algorithm:

CLusters similarity function:

I changed the similarity function such that it merges two clusters if the average similarity of every pair of incidents is above the similarity threshold. This allow to avoid randomness when comparing two clusters by two patterns only.

Incident similarity score:

iSquad algorithm compares only anomalous dimensions. The similarity of two incidents is the fraction ( # of similar anomaly/ # of anomalous metrics). I changed it to include non anomalous metrics but i give more points to a metric if the two incidents are similar and the metric has an anomaly.
