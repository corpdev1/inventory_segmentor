Initially, the system was tested automatically. It was tested with three settings:

  • 20 minutes of activity, in which the second 10 minutes has CPU saturation.
  • 90 minutes of activity, in which the middle 30 minutes has CPU saturation.
  • 15 minutes of activity, in which the middle 5 minutes has CPU saturation.

In the first case, when the anomaly was detected, the CPU metric had anomaly score much lower than the top five metrics (CPU metric: 0.013322416152928498, Top ranked anomaly: 0.036697524759120144, 5th ranked anomaly: 0.028172946552678355).

To test the ranking performance of FluxInfer, the anomaly was manually marked in the 90 minute dataset and tests were performed. The time windows were centered around the anomaly. The increase in the CPU metric is marked as the point of anomaly. Two window sizes were tested. See below for the results.

We can see that the CPU metric is given a low rank. The plots of the top 5 metrics, the CPU metric and the metric called questions (the number of client queries executed) are shown below. Many of the database metrics behave similarly to questions, where the metrics show activity before CPU saturation and then have very less activity when CPU saturation starts. The goal is to correctly capture the negative correlation that CPU saturation is having to so many of the database metrics.

The literature says that Fisher Z test requires a sufficient number of samples. We can see that the ranking of the metrics has not changed considerably between these two windows. This shows that the smaller window (96 samples, 1 sample per 10 seconds) appears to be good enough.

In order to better understand about Fisher Z-test and weighted PageRank the following experiments were done. Many of the time series along with calculation of the p-value of Fisher Z-test had to be examined manually in order to figure out these experiments. Check the bottom of this link for the plots of all the time series. The experiments are:

  • A small graph with 7 metrics (the top 5 metrics, the CPU metric, the metric called questions).
  • A graph with all nodes but with unweighted edges, where only edges with high weight (p_value < 1e-5) are retained and assigned a weight of 1.

See below regarding how Fisher Z test captures the correlation between pairs from a set of 7 metrics (the top 5 metrics, the CPU metric, the metric called questions). The time series are plotted and the Pearson correlation and the p-value of the Fisher Z test for the pairs are listed.

  • Two more tests were performed with the data generated by Karim and Dengke. The results are at the end of this page.

One can notice the clustering of innodb, network and the rest of the MySQL metrics. In the ranked scores, there is similarity between the two cases.

Check this link for more results and conclusions.
