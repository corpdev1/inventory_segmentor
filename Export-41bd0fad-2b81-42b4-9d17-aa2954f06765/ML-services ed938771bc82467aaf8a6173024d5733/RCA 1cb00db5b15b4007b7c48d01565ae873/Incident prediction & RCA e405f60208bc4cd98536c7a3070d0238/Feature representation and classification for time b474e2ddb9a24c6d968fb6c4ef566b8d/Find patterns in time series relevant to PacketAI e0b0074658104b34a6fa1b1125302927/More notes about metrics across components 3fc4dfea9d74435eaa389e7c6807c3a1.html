More notes about metrics across components

@Hariprasad Kannan wrote:

These plots are based on raw time-series. Check here for plots with data aggregated over time windows.

Note: Each of the metrics is in the form of groups. The groups can be of size: CPU - 16, memory - 2, disk I/O - 2, network -4. While looking at the plots, all the cases of each group were looked at. If one plot is similar to all the plots of that group, only that plot is included here. This is usually true for CPU metrics. For network, metrics w.r.t. bytes and packets are similar.

Observations

  • There is variation in behavior of all the metrics across technologies.
  • All Rabbitmq metrics show activity in the form of sparse groups.
    • It could be happening only in the case of Affluences.
  • Many network metrics are sparse. In some cases, the time-series takes only certain value(s).
  • Disk I/O metrics are sparse across technologies but show different patterns.
  • Memory metrics are taking low values in all cases. In some cases, the values are very low.
  • Need to understand what is present in Affluences instances like https://s3.console.aws.amazon.com/s3/buckets/packetai.ingest.affluences?prefix=mad_metrics_output/6040a96cdcc614001153fc55-linux6040eafa3a9e9f0012cebfd4/ which have only Linux and Docker metrics.
  • The time stamps for RabbitMQ are not consistent w.r.t. the S3 files from which the data is taken. The S3 files are chosen such that the timestamp in the filename falls between April 1st 00h00 and April 3rd 00h00. The time-series data is extracted from these files. For all the other technologies, the plots also match this time range. However, for RabbitMQ the plots are between middle of March 27th to April 3rd 00h00.
