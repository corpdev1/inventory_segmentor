The problem

In the sparse vs non-sparse identification experiments, the main challenge has been the clear labeling of the time-series as being sparse or not.

There are several time-series that can be clearly identified as being sparse. However, there are many problem cases also. The problem cases are either misses or false positives, depending on how strict is our condition to identify sparsity.

These problem cases are of the following nature:

  • They appear to be made of sparse spikes when seen over a longer (two day) time window. However, when seen over a smaller time window, the sparse spikes are less or missing. Instead, the time-series go up and down in a noisy manner or in the form of plateaus and troughs, which is not characteristic of sparse time-series. Sparse time-series are expected to have low and high values, where the low values are constant (or moderately noisy) and the high values are the spikes.
  • They appear sparse when seen over a longer time window because of occasional spikes in that larger time window. In some time-series, the spikes happen more often, in some cases less. So, it is difficult to decide a suitable time window if the spikes are rare.

In this experiment, these problem cases are to be more clearly identified.

The approach used to identify sparse vs non-sparse is simple and intuitive:

  • First the time series is processed where the exponential moving average is subtracted out. This helps in removing the effect of local trend.
  • For the resulting time-series, the values are assigned to histogram bins. We use 10 histogram bins.
  • If the bins corresponding to the lowest values have a considerable percentage of the samples, then the time-series is identified as being sparse. We look for 80% of the samples to be present in these bins.

Cases where this model can fail:

  • As noted earlier, if the time window has no spikes, then it is a problem. But this will be a problem for any time-series classification method because the time-series is not showing the behavior it should in the time window considered.
  • If spikes occur too often, then a considerable fraction of the time-series is present in the spikes. It is not 20% or less as the model expects sparse time-series to be.

The parameters for this model are:

  • What is the size of the time window?
  • How many lowest value bins do we look at?

The problem cases are expected to be very sensitive to these settings. In these experiments the following settings were tried in order to identify the problem cases:

  • The range of values of the bottom bins is narrowed down in order to see how these problem cases are identified as when this happens. The observed range of value are: bottom 3 bins, bottom 2 bins and bottom bin only.
  • The behavior of the time-series over smaller time windows are being observed, in order to see whether the label assigned at a larger time window (2 days) still holds in the smaller ones (1 hour and 6 hours).

For ground truth labeling, the time-series were visualized over a two-day window and if they appeared to be made of spikes, they were labeled as sparse. Thus, many of the time-series were given the ground truth label of sparse.

Analysis with MAD output

Of the settings tried, a setting that will give good precision (but poorer recall) is that of having two days time window and of using bottom bin only to model the low values. Smaller time windows are missing out the occasional spikes. Considering more of the low value bins is not sufficiently penalizing non-sparse behavior.

Thus, the misses that we encounter in this setting are the challenging cases. Many of them are not actually sparse, when we take a closer look and should be labelled as non-sparse.

Take-aways

  • To start with we can apply the approach that considers a two day time window and that models the low values using the bottom histogram bin only.
  • We need to properly choose the time window over which we decide sparsity.
  • We need to properly decide what behavior is considered as sparse and what is not.
    • We need to check which sparse time-series are giving more trouble for MAD, especially after setting the optimal weights and after suppressing false positives with SIRE.
  • Pre-processing (subtracting exponentially weighted moving average) reveals sparse behavior in some time-series. How is MAD performing on these time-series?
  • As we identify more time-series as those that we want to classify as sparse and those that we don't want to classify as sparse, then we could train a classifier based on general time-series features (like Rocket).

Some observations

  • A metric category (main e.g., disk I/O) need to behave the same way across technologies or even different components of the same technology.
  • There are many time-series that are made of spikes. This is observed across many technologies.
