Next steps

  • Look for surely periodic cases to start with: look for multiple peaks in the ACF, with more or less equal spacing (Anodot's approach).
    • Will require a longer time window, in order to look for multiple peaks in the ACF.
    • Could lead to period detection misses when there is trend.
    • More discussion about this below.
  • Should the first time period be at least of height 0.1? If the first time period is weak (ACF peak < 0.1) and it is filtered out, then the next inferred time period has a strong peak. Usually, both the first weak peak and the second strong peak are false positive.
    • However, cases like the above rabbitmq could still pass this test. Since, in these cases the first validated time-period corresponds to a relatively strong ACF peak.
  • Trend filtering: To minimise misses in periodic time-series with trends.
    • Set trend parameter based on minimum time period that is to be inferred.
    • Some misses are caused by level shift (check whether level shift can be adjusted using trend filtering).

Using multiple peaks in the ACF to validate a time period

Erie 1860 (Great lakes dataset)

  • Anodot is only based on the ACF. Anodot applies band-pass filters on the time-series to create three time-series on which time-periods of particular range of values could be inferred. Thus, it can infer multiple time periods.
  • ACF+PSD approach (what we have been mainly testing) filters only after validating a time-period. However, we are considering to have a minimum time-period that can be validated based on the length of the window used for analysis. This is similar to the band pass filtering by Anodot.
