Objective

Possible objectives are:

  • Given low level metrics, forecast high level KPIs or detect anomalies in high level KPIs.
  • Given a measured high level KPI, perform root cause analysis.
  • Forecast a measurable high level KPI directly.

  • For forecasting: There is an approach based on Prophet which will work for one KPI at a time.
    • The high level KPI should be measurable directly.
    • If there are low level metrics and a high level KPI that are related, then the high level KPI can be forecasted based on low level metrics.
  • Good to know about other packages that give a vector output.
  • Scalability is always an important concern.

Main challenges

The following are related to each other. Addressing one will help with the other:

  • Need to think about cold starting the procedure.
  • How to define high level KPIs?
  • How to measure high level KPIs?
  • Identify concrete problems - the low level metrics and the high level KPIs.

What are the inputs to the algorithm?

  • Raw values of the low level metrics.
  • Anomaly scores for the low level metrics from MAD.
  • Both.
  • Raw values of the high-level KPIs.

Need to know:

  • What problem do we want to address, first? prediction or anomaly detection or root cause analysis.
    • If a KPI can be measured, people usually perform root cause analysis.
  • Typically, how many low level metrics are there in our components?
    • Roughly, tens per component for us.
  • Typically, what are the high level KPIs?
    • Are these three enough for the time being?
      • On/Off; Latency; Number of errors.
  • What are some concrete examples of analysis performed on the output of anomaly detection algorithms running on low level metrics?
  • Can a forecasting algorithm be good enough to forecast an anomaly?
    • Usually, forecasting seems to be used for anomaly detection by comparing forecasted with actual value.
  • Suppose, we have several different runs of time series data (with both input variables and output variables), what are the good machine learning techniques that can learn a model of the temporal behavior? Prophet is designed to work for only one run of time series data and it predicts for time instances beyond that run.
  • What is a framework like atspy (https://github.com/firmai/atspy) automating? In the backend, it connects to several existing algorithms but it currently works for univariate data only.

How to define and if possible measure high level KPIs

  • Could we define rules relating lower level metrics to high level KPIs?
    • https://www.stackstate.com/blog/relating-it-issues-to-business-kpis-with-aiops
  • Could we cluster lower level metrics and see whether we can assign a meaningful KPI to the clusters?
    • The following is a very high level article: https://www.districtdatalabs.com/using-machine-learning-to-create-new-kpis
  • Reading further, it looks like many KPIs can be defined with some parameters like thresholds. Thus, many high level KPIs can be measured based on other low level metrics.
    • IT e.g.: latency can be defined based on a percentile and a threshold (e.g., 95% of the requests should be processed within 300 ms).
    • Business e.g.: https://www.sqlshack.com/how-to-automatically-create-kpis-in-sql-server-reporting-services/
  • What are some high level KPIs that can be defined based on low level metrics but cannot be measured directly? Thus, they have to be detected or predicted based on low level metrics.
  • Repairable system and the related KPIs: associated with mean time between failures (MTBF).
  • Non-repairable system and the related KPIs: associated with mean time to failure (MTTF).

Root cause analysis of KPIs

  • Predicting high level KPIs from low level metrics and performing root cause analysis for anomalies in high level KPIs seem to be two closely related problems. Could we "reverse engineer" what is done in the context of root cause analysis of problems in KPIs and develop a system that can predict KPIs?

Suitable KPIs for Prophet

  • The high level KPI should be measurable.
  • The KPI should take continuous values.
    • Thus, the hard disk failure prediction problem (mentioned below in the datasets section) is not suitable for Prophet. Because the KPI is binary: either the hard disk is working or not working.
    • See more here: https://github.com/facebook/prophet/issues/1379; https://github.com/facebook/prophet/issues/1153

Issues/Doubts regarding Prophet

  • With vector valued input, the values of the additional regressors should be known in the predicted time window, also.
    • For e.g.: https://towardsdatascience.com/forecast-model-tuning-with-additional-regressors-in-prophet-ffcbf1777dda
  • Generally, how long should be the number of historical samples for the algorithm to perform well?
    • According to https://docs.microsoft.com/en-us/azure/machine-learning/how-to-auto-train-forecast: Prophet works best with time series that have strong seasonal effects and several seasons of historical data.
  • Prophet has scalability issues: Refer, Seagull paper (https://arxiv.org/abs/2009.12922)
  • According to the KDD 2019 tutorial (refer below), inference is slow.

Other approaches ( simple and/or with code) for vector valued input

Also, the following approaches can be easily extended to vector output.

  • https://www.analyticsvidhya.com/blog/2018/09/multivariate-time-series-guide-forecasting-modeling-python-codes/
    • Uses statsmodels (https://www.statsmodels.org/stable/index.html).
  • https://machinelearningmastery.com/how-to-develop-machine-learning-models-for-multivariate-multi-step-air-pollution-time-series-forecasting/
    • Linear regression models from scikit-learn.
  • http://cs229.stanford.edu/proj2015/194_report.pdf (KPI-Driven Predictive ML Models Approach Towards Municipal Budgeting Optimization)
  • https://www.kaggle.com/pavansanagapati/anomaly-detection-credit-card-fraud-analysis
    • Uses isolation forests (precursor to robust random cuts approach).
  • auto_arima from pyramid-arima: https://towardsdatascience.com/anomaly-detection-with-time-series-forecasting-c34c6d04b24a
    • According to forecastTCN: Auto-Regressive Integrated Moving Average (ARIMA) performs best, when the data is stationary. This means that its statistical properties like the mean and variance are constant over the entire set.
    • According to Seagull paper: Arima models take a lot of training time but have very low inference time.

Other more sophisticated approaches for vector valued data

  • https://gluon-ts.mxnet.io/
    • Refer "Neural forecasting: Introduction and literature overview" for TensorFlow (https://www.tensorflow.org/probability/api_docs/python/tfp/sts) and PyTorch (https://github.com/MSRDL/Deep4Cast) based solutions. Compared to these, gluonTS offers more algorithms, better documentation.
  • sktime: A unified interface for machine learning with time series (https://arxiv.org/pdf/1909.07872.pdf)
    • Looks like only univariate time series are supported for forecasting. Conclusion based on:
      • https://arxiv.org/abs/2005.08067: Forecasting with sktime.
      • List of algorithms and tools supported: https://github.com/alan-turing-institute/sktime/blob/master/ESTIMATOR_OVERVIEW.md
    • https://github.com/alan-turing-institute/sktime
    • Depends on scikit-learn.
    • Nice point from the website: Many of these tasks are related. An algorithm that can solve one of them can often be re-used to help solve another one, an idea called reduction. sktime’s unified interface allows to easily adapt an algorithm for one task to another.
  • ForecastTCN: https://docs.microsoft.com/en-us/azure/machine-learning/how-to-auto-train-forecast
  • A recent exceptionally good approach: https://github.com/philipperemy/n-beats
    • The related works section of the paper is also nice.
  • N-Beats gave better results than ES-RNN, which won the M4 competition.
    • https://pypi.org/project/ESRNN/

Importance of features

Good features, by themselves, could lead to very good results.

  • The Importance of Features for Statistical Anomaly Detection by Goldberg and Shan, 2015.
  • AIOps for a Cloud Object Storage Service, Levin et al, 2019.
  • N-BEATS paper talks about using the output of statistical techniques as features for the learning algorithm.
  • Several ideas from Eamonn Keogh (https://www.cs.ucr.edu/~eamonn/) and colleagues: SAX, Shapelets, Matrix profile (refer, STUMPY above) etc.
