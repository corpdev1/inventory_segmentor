Important take-aways for PacketAI

  • Look at the system in a hierarchical manner at component level and service level.
    • Service level outages consist of various corresponding component level outages.
    • This hierarchical representation can be extended to our case.
  • This hierarchical representation is built using a Bayesian graph learning approach. We have already come across such approaches in RCA. In this paper they use the graph based representation for both prediction and RCA.
  • Rule based alerts gives reasonable results for component outage prediction.

The goal of the paper

Predict outages (component level and service level) of services hosted in a cloud system.

Details about machine learning

  • Uses alerts: failure signals from rule based status monitors.

    An alert is defined by comparing a time-series with a threshold or by looking for key words in logs (check Automatically and adaptively identifying severe alerts for online service systems). Usually, the time-series can be obtained from metrics but it is possible for logs (by aggregating log based data. Check temporal features of this paper).

  • An alert can itself lead to a time-series. What exactly is the numerically value associated with an alert time-series?
    • The paper doesn't describe this clearly.
    • Could be the number of times an alert is created in a time window. That is what is claimed in Section 6 of Real-Time Incident Prediction for Online Service Systems.
  • The outage of a component and service is also defined based on an alert.
  • Data driven approach to capture the complex manner in which various alerts can predict outages.

Bayesian network

  • To relate all the alerting signals.
  • Based on FCI algorithm.
  • Used only for connectivity and not causal relationship: We can look at it as feature selection.

Other details

  • XGBoost based prediction
  • SMOTE based sampling for data imbalance.

About the data

  • One year outage dataset collected from a Microsoft cloud system.
  • Six representative services from tens of data centers.
  • Time step of one hour.

About the components and services

  • The results are based on the following components:
    • The Storage Location.
    • Physical Networking.
    • Storage Streaming.
  • The results are based on the following services:
    • The Web Application.
    • Cloud Network.
    • The Microsoft Cloud System Operation Service.
