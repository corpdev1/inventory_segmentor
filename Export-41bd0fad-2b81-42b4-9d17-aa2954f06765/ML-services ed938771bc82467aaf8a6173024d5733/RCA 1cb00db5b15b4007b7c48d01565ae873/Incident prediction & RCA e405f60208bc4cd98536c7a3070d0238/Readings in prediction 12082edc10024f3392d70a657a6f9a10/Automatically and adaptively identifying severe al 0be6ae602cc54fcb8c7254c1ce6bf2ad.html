Important take-aways for PacketAI

  • Utilizing a suitable set of features leads to good performance.
    • This could immediately help with the SIRE project. We could look for more features along the lines mentioned here.
  • Like other papers, using both logs and metrics at the same time helps.
  • Topic models based vector representation of text could be useful to us. Especially papers like "A Biterm Topic Model for Short Texts" by X Yan et al, WWW 2013, which are good at dealing with short texts like logs.
  • Use the characteristics of P-1 alerts below to automatically create labels regarding alert severity.
  • Could the algorithm FT-tree (used for alert parsing) be useful to us?

The goal of the paper

To better characterize the severity of alerts generated in a system.

About Alerts

  • Ways to create alerts:
    • Thresholds for metrics.
    • Keyword matching for logs.
  • Alerts can be categorized as: P1-critical, P2-error and P3-warning
  • A P1 alert is characterized by:
    • Number of metrics experiencing anomalies: Multiple metrics (such as success rate, transaction volume) all experiencing some anomalies.
    • Time of occurence: During busy hours.
  • An alert is associated with a resolution record: text describing the action taken by on-call engineer.

Details about Machine Learning

  • Multiple features extracted from alerts are needed to determine alert priority in a complex system.
  • During training, the severity scores are automatically assigned to the alerts based on resolution records.
    • The resolution records are clustered based on TF-IDF vectorization and k-means.
  • For testing alert is labeled as severe or non-severe according to whether it is associated with a ticket.
  • Mentions how ranking based approach can help with data imbalance. Doesn't mention sampling.
  • XGBoost based pointwise ranking algorithm.
    • Assigns an absolute severity score.
    • Compared to LambdaMART, which gives only relative ordering between the inputs.
  • Alerts over 15 minutes time windows are ranked.
  • Rank 100 alerts in about 2.4 seconds.
  • Trains incrementally.

About the features

  • Textual: topic and entropy.
  • Temporal features: frequency, seasonality, count, inter-arrival time.
  • KPIs (Business KPIs and Server KPIs): univariate and multivariate anomaly features.
  • Alerts with lower frequencies are more likely to be severe.
  • Time of the alert:
    • During busy hours or not.
    • Day or night.
    • Weekday or weekend.
  • Use rule based severity as a feature.
  • Source of alert:
    • Application; OS; Network; Memory; Middleware; Others.
  • According to their experiments, the alert features are more powerful than KPI features.

About the data

  • 18 month long dataset.
