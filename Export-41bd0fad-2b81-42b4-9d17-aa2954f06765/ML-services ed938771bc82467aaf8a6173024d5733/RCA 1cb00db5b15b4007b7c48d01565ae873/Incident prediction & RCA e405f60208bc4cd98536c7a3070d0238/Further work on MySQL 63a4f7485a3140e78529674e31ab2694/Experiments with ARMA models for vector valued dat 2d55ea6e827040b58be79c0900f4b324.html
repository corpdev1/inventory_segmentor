Experiments with ARMA models for vector valued data

@Hariprasad Kannan wrote:

In our use case, we want to take in a vector of inputs and predict a scalar or vector of outputs.

ARMA models are classic techniques used in time-series analysis, which have some advantages:

  • Low inference time (Refer Seagull paper).
  • Doesn't require too much data:
    • Note the comment here about exponential smoothing, which is another classic approach like ARMA.
  • Learning based techniques use features based on ARMA, exponential smoothing etc (Refer n-beats, a state-of-the-art approach).
  • Well studied.

Some disadvantages of ARMA models are:

  • Training is computationally heavy (Again, refer Seagull paper).
  • Vulnerable to noisy data compared to machine learning based techniques.
    • "Machine learning algorithms can be applied to time series forecasting problems and offer benefits such as the ability to handle multiple input variables with noisy complex dependencies." from here.

At this point of time, it looks like there is no robust software package that takes vector input and predicts even a scalar (leave alone vector) as an output.

In the context of time series analysis, variables can be grouped in two ways: endogenous and exogenous.

  • Endogenous variables are the future predicted variables.
  • Exogenous variables are the variables that are used to make the prediction: these include the past values of the predicted variables and other variables.

Important constraint

Many ARMA based software packages allow multiple input variables. However, they expect the input in the form of the following:

  • For endogenous variables: past values are enough.
  • For exogenous only variables: values in the past and in the prediction horizon are needed.

This includes Facebook Prophet, pmdarima, SARIMAX in statsmodels. This is not useful for us. Because we have only past values for all of our variables. Only the following two implementations seem to be useful for us:

  • VAR and VARMAX from statsmodels.

  • VAR has limited prediction horizon. After a few steps (around 15) it outputs an average estimate. This is known in the community and it is mentioned here, for e.g.
  • VARMAX is highly sensitive to non-stationarity in the input. Thus, errors related to linear algebraic calculations were obtained at various stages of the algorithm's run.

    The linear algebraic errors were addressed in the following ways:

    • A Matrix is not positive definite that appeared at an early stage was addressed by considering longer lag and longer moving average windows (the Auto-Regressive and Moving Average parts of an ARMA model, respectively).
    • Next the following error appeared ValueError: Non-stationary starting autoregressive parameters found with enforce_stationarity set to True. One way to address this error is to manually set starting parameters. It is not yet clear how to do this, thus enforce stationary was set to False. Also, enforce invertibility was also set to False.
    • Another error that appears is Schur decomposition solver error which is discussed here in the context of SARIMAX, which was fixed by setting enforce stationarity to False. It is not solving the problem for VARMAX.
    • The following were also tried to see whether they can fix the linear algebra issues:
      • Not considering signals which are constant or have sparse activity.
      • Using more data to fit the model.
      • Considering a smaller set of variables.
      • Reducing the number of iterations of the fitting algorithm.

      The fitting algorithm has so far not completed an entire run and exited successfully. Linear algebra errors like LinAlgError: Matrix is singular keep appearing.

  • Also, the implementation of VARMAX in statsmodels is not very stable (for e.g., check here, here).

Thus, there is a serious lack of software packages that can take vector input and make prediction.

Encouraging stationarity

Classic techniques work better when the signals are stationary in nature. Look here for an intuitive explanation and how to test for it. Here is one more reference about how to test for stationarity. Especially, trend and seasonality effect need to be removed. There are ways to identify and compensate for non-stationarity:

  • Differencing: Difference of adjacent values for removing trend. Difference of values that are separated by a time period for removing seasonality.
    • Estimating seasonal time period is a problem by itself: here, here.
    • Seasonality can be handled in the form of time based features like time of day, month of the year etc. The choice depends on the problem.
  • Log transform for better stationarity of variance. Check here.

This could be relevant for learning based techniques also because removing the effect of trend and seasonality is mentioned in a lot of places.
