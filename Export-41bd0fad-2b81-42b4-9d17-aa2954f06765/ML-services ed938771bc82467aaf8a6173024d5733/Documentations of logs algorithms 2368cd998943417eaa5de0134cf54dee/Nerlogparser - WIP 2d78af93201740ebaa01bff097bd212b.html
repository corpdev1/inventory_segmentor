Test Examples

MacOS

Logs

Log : Mar  4 00:39:27 pc-1 Google Chrome Helper[2107]: Libnotify: notify_register_coalesced_registration failed with code 9 on line 2835

Mar  4 00:39:28 pc-1 syslogd[58]: Configuration Notice:
	ASL Module "com.apple.cdscheduler" claims selected messages.
	Those messages may not appear in standard system log files or in the ASL database.

Parsed

{"timestamp": "Mar 4 00:39:27", 
"hostname": "pc-1", 
"message": "Google Chrome Helper[2107]: Libnotify: notify_register_coalesced_registration failed with code 9 on line 2835"} 

{"timestamp": "Mar 4 00:39:28", "hostname": "pc-1", "service": "syslogd[58]:", "subservice": "Configuration Notice:", "message": ""}, 

{"message": "ASL Module \"com.apple.cdscheduler\" claims selected messages."},

  • Parsing is correct
  • Multiline is not supported

Conclusion

The technique is quite promising.

Advantage :

  • Parse logs : could replace Logstash Groks in the future
  • Fully automatic : no need for configuration

Disadvantage :

  • Needs to be trained and maintained
  • Works better for OS logs
  • Package written in python 3.5 which has reached its end of life
