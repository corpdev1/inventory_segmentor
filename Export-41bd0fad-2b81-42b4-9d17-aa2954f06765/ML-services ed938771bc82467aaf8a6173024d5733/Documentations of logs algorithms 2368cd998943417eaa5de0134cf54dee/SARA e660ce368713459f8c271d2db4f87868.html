Introduction

The intuition behind the SARA model is : if a log is very rare, and contains negative words, it is likely to be an anomaly.

To compute these two metrics, SARA is based on two main algos:

  • Rareness : check if a log has been seen before
  • Sentiment : check the polarity of the logs in terms of negativity. Words like, error, critical, failed are an example of negative words in the domains of IT.

Clean logs

Before computing both algorithms, the logs are passed through two main cleaning steps

Content extraction

All the logs contains two main parts, the header and the body :

For instance, consider this log :

Mar 23 20:35:42 pc-1 Google Chrome Helper[1096] <Error>: Libnotify: notify_register_coalesced_registration failed with code 9 on line 2835

This log is parsed in two parts :

Header : Mar 23 20:35:42 pc-1 Google Chrome Helper[1096] <Error>:
Body (content) : Libnotify: notify_register_coalesced_registration failed with code 9 on line 2835

This part is done in logstash as a part of a preprocessing step for LAD

Preprocessing

The preprocessing step is a custom cleaning that tends to remove as much dynamic parts on the logs as possible in order to harmonise them for further comparison

The main preprocessing steps are :

  • lowercase
  • Keep alphabets only
  • Remove unichar tokens
  • Remove english stopwords

Rareness Analysis

The rareness analysis is used to compute if a log is rare.

To achieve this, a simple algorithm is followed :

  • Collect a set of N logs into a dataset
  • Compare all the new logs to the collected logs beforehand by compute the cosine similarity between them
  • The score of the similarity is the maximum distance between the new log and the dataset
  • If the score is larger than certain THRESHOLD update the dataset with the new log

Sentiment Analysis
