AutoEncoder of Template Sequences (AETS)

The goal of this model is to find anomalies over a sequence of templates of logs.

The idea is to train an AutoEncoder architecture over a sequence of normal sequence of log templates, and try to distinguish between abnormal sequences and unseen normal sequence afterwards.

Introduction

Definition

The AutoEncoder (AE) is an Encoder-Decoder architecture that tries to predict the input.

Many use cases are presented that can be solved by an AE :

  • Anomaly detection : teach the AutoEncoder the normal behaviour and use it to distinguish between normal and abnormal afterwards
  • Dimensionality reduction : find a new representation of the input data
  • Denoising : learn to reconstruct denoised input from a corrupted version

Study Dataset

The dataset is obtained from LogPAI, it consists of logs coming from HDFS production environment.

The logs from the dataset are passed through a template extraction step as described above, to extract the template of each log.

Then a sequence of templates is constructed by grouping over the SessionID (BlockID in our case)

Each SessionID is labelled with Normal or Abnormal, which are used to validate the model.

Model and Architecture

The idea behind the architecture of the model is inspired from the Seq2Seq models used mainly in machine translation domains

The goal is to encode a sequence of tokens (templates) and decode its output to generate the another sequence, which is in our case the same sequence.

Learning to construct the same input push the model to learn a latent representation of the normal sequences. We expect that the model fails to reconstruct an abnormal sequence since that it differs from the normal one.

The architecture is :

  • Encoder :
    • Embedding Layer
    • RNN layer (LSTM or GRU)
  • Decoder
    • Embedding Layer
    • RNN layer
    • Softmax

The model encodes the input by passing through an embedding layer (for a better representation) and an LSTM layer to learn the sequences.

The hidden state vector output of the LSTM encoder (called the context vector) is used as input to the decoder that tries to decode the desired target by generating one token at a time.

The loss is the average of the losses at each step of the decoding, which is, the average of the losses output from a classification model over all the possible templates.

The decoder stops outputting when it output the EOS sign, or when the maximum length of the sequence is reached.

Teacher forcing was used which is, the concept of using the real target outputs as each next input, instead of using the decoder’s guess as the next input. Using teacher forcing causes it to converge faster but when the trained network is exploited, it may exhibit instability.

Challenges

  • Ressources for training : the model take a lot of ressources (time and cpu) to fit a model.
  • Threshold choice : to decide on the anomalies, we must fix a threshold. Since the loss is not normalised, this threshold could be dynamic and based on the training outcome.
