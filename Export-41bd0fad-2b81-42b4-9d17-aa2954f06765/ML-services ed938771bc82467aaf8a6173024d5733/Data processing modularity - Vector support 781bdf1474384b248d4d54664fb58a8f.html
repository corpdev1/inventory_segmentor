Data processing modularity - Vector support

Introduction

  • Many users have tools in place to process logs. For example, Vector, logstash etc
  • Ideally, when we deploy our agents we impose minimal to no change to their existing workflow

Overview of Vector

Simple tool to:

  • collect
  • transform
  • route

data, logs and metrics.

Just like logstash, Vector can be used as agent to collect data or as processor only to only process data collected by other collectors.

Vector integration

We have 4 options:

Option1: local Vector (client infra) without corr tags

  • no need for our agent installation since collectors are already in place in
  • at least tagging of data sources
  • correlation of logs and metrics is not guaranteed
  • RCA is not possible

Option2: local Vector (client infra) with corr tags

  • no need for our agent installation since collectors are already in place
  • correct tagging of data sources and links between data sources, on client side
  • supporting tags on our side and rely on tags to:
    • have list of components
    • construct physical topology
  • correlation of logs and metrics is possible
  • RCA is possible

Option3: local Vector (client infra) as Man-in-the-middle

  • our agent collects logs and metrics
  • data is sent to local vector
  • local Vector transforms data, only updating user-space data (not packetai meta data)
  • vector routes data to our kafka

Option4: integrate Vector in our pipeline

  • replacing logstash by Vector
  • openning Vector UI to users to do transforms

Rollout plan

  • We go incrementally providing templates to clients first - option1
  • The implementation must be smoothly extensible to option3

Detailed implementation (Option1)

Requirements

  • HTTP endpoint
  • adapting Vector data format to PacketAI pipeline

Reminder

  • no need for our agent installation since collectors are already in place
  • at least tagging of data sources (componentID)
  • correlation of logs and metrics is not guaranteed
  • RCA is not possible

Configuration

Sink config

sinks:
  packetai_sink:
    type: http
    inputs:
      - packetai_transform
    uri: https://app-metron.packetai.co/endpoint
    acknowledgements: null
    batch: null
    compression: none
    encoding:
      codec: json
    healthcheck: null

Transform config

transforms:
  packetai_transform:
    type: remap
    inputs:
      - metron-sources
    source: |-
      . = parse_json!(.message)
      here is where to inject the transformation
