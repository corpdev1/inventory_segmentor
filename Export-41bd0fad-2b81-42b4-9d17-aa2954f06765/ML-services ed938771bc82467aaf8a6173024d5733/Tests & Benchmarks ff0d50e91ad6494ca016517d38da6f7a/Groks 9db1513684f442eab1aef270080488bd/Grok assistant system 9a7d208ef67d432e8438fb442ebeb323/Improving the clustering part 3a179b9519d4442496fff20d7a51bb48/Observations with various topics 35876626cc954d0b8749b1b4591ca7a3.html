Observations with various topics

Executive summary

  • The masking-based variant of the clustering algorithm improves the quality of clustering.
  • The custom masking function to handle quoted text is suitable for identifying quoted texts at the same level at which a grok pattern parses a raw log into smaller parts. This quoted text mask works seamlessly with the quote based delimiter used by the current clustering approach.
  • The method improves on cases that defeated the previous version, without deteriorating on cases that we successfully handled.
  • Except for linux syslogd component logs, all logs are successfully parsed with specific (aka not greedydata) groks.
  • The recommendation is to switch to this masking-based variant of clustering.

Observations

@Hariprasad Kannan wrote:

  • The final approach tried is described here. It is referred to as the "proposed approach" in the following.
  • In the following table, the clustering method used while using the grok-bot end-to-end, is different from the current clustering method of the grok-bot. Thus, Representative logs (current approach) with the counts for the current clustering approach, does not overlap in some cases with the raw logs counted while using the grok-bot end-to-end (Logs during grok-bot usage).
  • The column Sufficient number of representative logs represents a range of logs that the user needs to see in order to be sure about the structure of the logs present in the topic. Thus, in the initial iterations, the user will minimize/avoid the use of GREEDYDATA, so that he/she can be presented a variety of raw logs by the grok-bot. At one point, the user will be able to decide the use of GREEDYDATA. This will lead to matching with a huge range (if not all) of raw logs. This process could repeat a few times (even after using GREEDYDATA to some position in the grok pattern) before the grok-bot matches all the raw logs.
  • Suppose the topic has raw logs with a single structure. It is still a good idea for the user to see 2 to 3 raw logs, so that he/she is clear about the nature of the logs in that topic.
  • For some components (especially, linux system), the Misses and Extras are marked as >1 because while using the grok-bot it is up to the user to decide when to stop entering temporary custom patterns for the content and use %{GREEDYDATA:content}. The logs in these topics have varying unstructured content part. Once %{GREEDYDATA:content} is used for the content, most (if not all) raw logs will be matched.
    • As a suggestion: It is better that the user sees or is forced to see a sufficient number of raw logs for such topics. So the user should avoid %{GREEDYDATA:content} and use temporary custom patterns in the initial interactions. These patterns are temporary because many of them will be grouped together and will replace by GREEDYDATA when entering the grok patterns into logstash.
    • The proposed clustering approach is showing extra representative logs in such topics because of finding masking pattern matches in the content.
    • In many cases, extra representative logs shown by proposed approach is desirable. It lets the user of the grok-bot to see more variety of cases at the beginning itself (before the grok-bot presents cases as unmatched raw logs).
