Experiment setup

The evaluation of LogFrequency pipeline was done using data of Affluences, Zero Gachis and cwallet for the period from 2021-11-01 00:00:00 till 2021-11-16 00:00:00 as follows:

  • Log count data from 2021-11-01 00:00:00 till 2021-11-08 14:50:00 was used to identify the shape of time-series and for model training
  • Log count data from 2021-11-08 14:50:00 till 2021-11-16 00:00:00 was used for model evaluation

Evaluation charts

For each client we've generated the evaluation charts. They are organized as follows:

  • anomalies folder contains charts for data in which we found anomalies
  • no_anomalies folder contains charts for data in which no anomalies were found
  • not_deployed folder contains charts for topics without deployments (the decision regarding the model deployment to the topic was based on the result of the classifier and the predicted shape. We did not deploy for data of sparse shape)

Each chart contains the following information:

  • data source of the form infraID-agentID-componentID
  • predicted time-series shape
  • deployed models (HB (stands for the "histogram bins") and/or Skyline)
  • train and test data split is highlighted with color
  • abnormal points colored red: abnormal points that user would receive
  • abnormal points colored black: abnormal points filtered by noise reduction algorithm and user wouldn't see

Model assignment

The model assignment was done as follows:

  • “sparse data with no patterns”: no models
  • “usually the same values observed”: HB
  • “random noisy data”: HB + Skyline
  • “dense data around the mean value”: HB + Skyline

Note: the point is anomalous if all detectors gave a positive result, i.e.

HB: True, Skyline: True → the point is abnormal

HB: False, Skyline: True → the point is not abnormal

HB: True, Skyline: False → the point is not abnormal

Observations

  • Affluences
    • Some False Positives could be reduced by introducing pertinent alerting rules that measure the difference between the average number of logs and observed one (for example here, here and here abnormal points had log counts that were different from average number by no more than 5 logs)
    • Anomalies for 6040a96cdcc614001153fc55-docker-monitoring_prometheus were detected but not shown on Minima due to some bug → raised an issue @November 18, 2021
    • Probably need to review the definition of sparse data: some topics are not covered (6040a96cdcc614001153fc55-docker-javaappsmith_appsmith-internal-server and 6040a96cdcc614001153fc55-docker-redisappsmith_redis)
    • Level shift was not detected for 6040a96cdcc614001153fc55-docker-nodeapp_app-api and 6040a96cdcc614001153fc55-docker-nodeapp_app→ due to AND condition: HB detected level shift immediately and quickly adapted while Skyline did it with some delay
  • Zero Gachis
    • Many time-series changed their shape from sparse (example) and need to be reevaluated with data classifier → the proof of necessity for weekly data shapes updates → think about the automation
  • cwallet
    • All data about exact numbers of detected and sent to the client anomalies was erased since the cluster was deleted → the results for this client are based on data stored on s3

Update @November 26, 2021 : adding absolute delta to log frequency pipeline

Absolute delta definition: an absolute difference between the observed value and Exponentially weighted mean (calculated in stream manner) of previous positive values

Decision rule: an abnormal point is FP if the absolute delta value is less than a threshold (10 by default)
