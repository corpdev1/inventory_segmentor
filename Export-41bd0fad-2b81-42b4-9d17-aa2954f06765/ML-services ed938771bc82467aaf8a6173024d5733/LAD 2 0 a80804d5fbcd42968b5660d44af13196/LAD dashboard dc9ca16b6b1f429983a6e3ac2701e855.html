PacketAI Design

General design

  • user can select logs by source - host - service
  • logs of same service could be get from across multiple sources and hosts
    • eg, logs of authentication_service (business service) could be found across mongodb, docker, nginx ....
    • same concept for across hosts
  • user can group logs by automatically generated patterns (log templates), built-in keywords (error, warn, info) or custom patterns, including custom keywords
  • each selection provides a search bar for facility
  • for each selected logs, we show:
    • count of logs
    • colour coding for presence of anomalies (including negative logs) , or explicit preence of built-in negative keywords (built-in list includes: error, fatal, critical, warning, debug, info). The colour indicator is expandable to show explanations and details
    • highlight of negative logs patterns/keywords on the UI and in the daily report emails
  • bar chart adapts to each selection of logs

Note

  • all features must work for docker, kuberentes, EKS, swarm ..
  • all features must work for auto-scaled (host or container) docker, swarm, kubernetes, ...
