Applying ML to Kube monitoring

Kubernetes is meant to be dynamic, users don’t care much about containers and pods disappearing and reappearing... hence, applying ML on container and pod metrics would not make sense. Anomaly detection would be applied on static elements such as:

  • metrics of deployments (representing business services)
  • UPIs such as global latency, throughput ...
  • cluster metrics, such as number of pods, number of containers, etc

  • agent collects kube metrics: container and cluster metrics
  • agent collects pod/container logs
