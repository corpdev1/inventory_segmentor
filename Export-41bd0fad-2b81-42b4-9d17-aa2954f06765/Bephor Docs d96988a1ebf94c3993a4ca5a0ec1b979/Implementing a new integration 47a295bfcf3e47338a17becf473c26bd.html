Implementing a new integration

To implement a new integration, three (parallel) tasks are necessary:

TTI: time to implement

0. setup

  • install the integration on the test platform
  • install Datadog integration
  • configure if necessary
  • launch it to generate the min amount of data to visualise data in the dashboard and get the field names, aggregation and type of chart
  • else, a shortcut would be just to look here for the list of fields https://docs.datadoghq.com/integrations/rabbitmq/

1. implement the technology discovery in the process microservice (TTI: 1h)

a. soft discovery, assuming default config parameters: (1h)

  1. we will focus on soft discovery for the first iteration of our product. The implementation is done by building a map of techno name; list of regex (for process name and command)
  1. this method even works for technos inside docker containers
  1. immediate targets:

    host technos

    1. mongo
    1. mysql
    1. docker
    1. java
    1. nodejs

    container technos

    1. mongo
    1. mysql
    1. java
    1. nodejs
  1. implement the link to Minima including the icon

b. hard discovery, assuming non-default config parameters: (4h but not necessary in first iterations)

1. search for the config file of the target technology

2. parse the config file and extract config parameters including

  • log paths

2. Integrate logs and metrics insights (TTI: 1h - 3h)

  1. if the integration is supported by metricbeat and filebeat then use standard dashboards (1h)
  1. else, build a custom insight module: (3h)
    • build a custom filebeat module
    • build a custom metricbeat module
    • build custom dashboards

3. build the Logstash pre-processing pipeline (TTI: 1h - 3h)

  1. get a sample of logs
  1. use a pre-built logstash grok if exists here:https://github.com/logstash-plugins/logstash-patterns-core/tree/master/patterns (1h)
  1. else, build a custom one using https://www.elastic.co/guide/en/kibana/current/xpack-grokdebugger.html. (3h)
