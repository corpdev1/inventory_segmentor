30.12.2020. ODFE 1.12 update:

Using admin role + admin tenant:

  • Alerting works as expected

Using non admin role + infrastructure tenant:

  • The creation of index patterns in Stack management requires to target specific index pattern that is available to the role and targeting a broader index pattern won't work (ex. index-* doesn't work but index-5fe0a8cf6fcb076de4878b54-* works)
  • To have a proper index search there is workaround granting indices:admin/resolve/index on index pattern * to user which enables him to list all of the indices instead of only the ones he has the permission to which is unacceptable(the workaround didn't work on our DEV)
  • These are the links to multiple discussion and a former issue we opened which seem to suggest it's a Kibana 7.9.1 issue and possibly won't even be resolved:
    • https://github.com/opendistro-for-elasticsearch/security-kibana-plugin/issues/529
    • https://discuss.opendistrocommunity.dev/t/security-issue-no-permissions-for-indices-admin-resolve-index/3959
    • https://github.com/opendistro-for-elasticsearch/security-kibana-plugin/issues/598
    • https://github.com/opendistro-for-elasticsearch/security/issues/893

  • The creation of alerts works after adding the predefined role for alerting alerting_full_access
  • To use alerts and monitors a cluster permission needs to be added to one of the users roles (cluster_all or individual cluster permissions)
  • The monitor page index drop down has to target the specific permitted index and the alerts can be created only for the permitted index of the role
  • With these permissions the user can unfortunately see all alerts and monitors regardless of his role permissions (out of the box, the alerting plugin has no concept of ownership and filtering alerts can be enabled using by limiting access by backend role)

Using non admin custom role(marketing, sales. dev...) + infrastructure tenant:

  • Everything works the same as the above (using non admin role + infrastructure tenant) but the listing of all alerts and monitors potentially isn't as impactful as when using multi-tenancy

Email notifications were added but require setup directly through ODFE security and Elasticsearch for the sender emails so it's not suitable for easy user/customer setup:

Old:

  • Alerting can be enabled in Open Distro with a set of security role(permissions) which can be found here: https://opendistro.github.io/for-elasticsearch-docs/docs/alerting/
  • These roles enable users to create monitors targeting their specific indices
  • The problem with Open Distro alerting is that is stores all the monitors/triggers/destinations in the same indices (unlike kibana objects which are saved in different indices for each user/tenant) which can be found here: https://opendistro.github.io/for-elasticsearch-docs/docs/alerting/settings/
  • This means that any user can see all the created monitors despite their infrastructure/tenant
  • All monitors are also ran by the admin user, which means that monitors can query all documents in all indices and do not consider the roles of the user who created the monitor: https://opendistro.github.io/for-elasticsearch-docs/docs/alerting/
  • The separation of monitoring using the security plugin is a an upcoming feature which is covered here: https://opendistro.github.io/for-elasticsearch/features/comingsoon.html
  • The running issue can be found here: https://github.com/opendistro-for-elasticsearch/alerting/issues/215
  • An official answer on the forum can be found here: https://discuss.opendistrocommunity.dev/t/security-integration-with-alerting/3334
  • https://github.com/opendistro-for-elasticsearch/alerting/issues/6
  • https://discuss.opendistrocommunity.dev/t/how-to-restrict-alerts-to-a-specific-user/1185
