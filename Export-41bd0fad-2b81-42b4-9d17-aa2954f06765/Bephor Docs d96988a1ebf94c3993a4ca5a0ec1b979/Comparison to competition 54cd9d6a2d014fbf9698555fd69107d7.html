Tech:

  • UI, especially alerts, when there are a lot of them it tends to slow down
  • Some personal configurations are limited for users so to put them into operation you should go to the support team, but however it is not any inconvenient that can not be resolved because they are extremely attentive.
  • Being based on the cloud can be somewhat slow sometimes but only for a few seconds so I think it is something that can be missed because it does not pass in a common way.
  • There are two things that I dislike about this: 1) if you receive a lot of messages, or are dealing with a lot of queries, the interface may become extremely slow. 2) There is only a limited number of subaccounts your institute can have, and for us that is just not enough.
  • Sometimes search behavior is not what it expected. for example search for a string auto triggers a search before adding additional filters to capture the relevant data. Also would like exception stack trace to highlight the specific project code the locate it faster.
  • The service as pay per quote for logz, sometime the quote fills up and there is not indication other than lack of logz, a switch over choice in case of a quote fill would be great.
  • Composing queries takes a little bit of work, but like anything else practice makes perfect.
  • You do get less control than if you're hosting ELK yourself, so there are some customizations that are unavailable to us. But it's worth the trade off for us. Also, there is a bit of a learning curve, though it's as easy to use as any of the competitors.
  • The UX was a bit not clear to me at first. I got used to it, though...
  • Also, we've wanted to create an automatic daily report that groups the distinct errors that occurred every day and emails it - it wasn't supported in our version (I think it was possible for paid accounts but the price was too high for a small startup like ours...).
  • Custom logstash filters must be applied by Logz.io staff. We build a test environment on site with custom grok filters, for some reason they were not compatible with Logz.io and took a week or two to get converted/rewritten.
  • Setting up certain filters and the addition of new log types needs to be done by support. But their support is amazing and they have a very fast turnaround.
  • Not able to see the parsing currently configured on the account.

    Not having Private insights which I hope is in the road-map.

    Alerting could be more sophisticated, for example - anomaly detection, resource starvation algorithms.
