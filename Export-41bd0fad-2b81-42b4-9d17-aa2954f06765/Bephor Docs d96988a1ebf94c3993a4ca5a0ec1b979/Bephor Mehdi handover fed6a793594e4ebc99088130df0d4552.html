Open Distro (OpendiostroEC2 repository)

Running the instance:

  • Start docker service: sudo service docker start
  • openssl-san-*.cnf: Required to create certificates, need to be modified with the proper targeted Kibana address (like. kb-staging-*)
  • create-certs.sh: Run the script to create all the required certificates
  • Create a load balancer for the instance + the record set
  • docker-compose.yml: CERTS and other configs are explained in the comments in the file, need to be modified with the proper targeted Kibana
  • All files with accounts/kibana endpoints need to be modified with the proper targets
  • sudo docker-compose up
  • Update the security inside of kibana:
    • sudo docker exec -it {containerid} sh
    • cd plugins/opendistro_security/tools
    • chmod +x securityadmin.sh
    • ./securityadmin.sh -cd ../securityconfig/ -icl -nhnv -cacert ../../../config/root-ca.pem -cert ../../../config/admin.pem -key ../../../config/admin-key.pem

    • Security needs to be updated on one elastisearch node but sometimes could require to update both
    • Load balancer health checks could take a lot of time
    • Update Accounts and apply

# ---------------------------- Elasticsearch Output ----------------------------

Kubernetes:

  • Connect to dashboard:
    • Select Kubernetes Context on desktop app
    • kubectl proxy
    • http://localhost:8001/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/#/login
    • To get the required login token:
      • kubectl -n kube-system describe secret $(kubectl -n kube-system get secret | grep eks-admin | awk '{print $1}')

  • Get pods: kubectl get pods
  • Get deployments: kubectl get deployments
  • Create pods: kubectl apply -f {configFileName}
  • Update deployments with new image:
    • kubectl scale deployment {DEPLOYMENT_NAME} --replicas={NUMBER_OF_PODS_NEEDED}
    • Destroy:
    • Create: kubectl scale deployment packetai-account-app --replicas=1
    • It means destroy previous deployment and recreate it
    • Scale to 0 host then to 1
  • Get the addresses of the mongo databases (example for DEBBY staging):
    • for ((i = 0; i < 3; ++i)); do kubectl exec --namespace default debby-staging-mongodb-replicaset-$i -- sh -c 'mongo --eval="printjson(rs.isMaster())"'; done

  • Port forward Kube MongoDB from mongo namespace for use with Compass or RoboMongo to local port 27020 example:
    • kubectl port-forward -n=mongo pods/mongo-mongodb-replicaset-0 27020:27017
  • Get pod info:
    • kubectl describe pods {POD_NAME}
  • Expose MongoDB ports(possibly target all replicas 0, 1 and 2):
    • kubectl expose pod debby-staging-mongodb-replicaset-0 --type=LoadBalancer

Helm:

MongoDB:

  • Add helm repository locally: https://github.com/helm/charts/tree/master/stable/mongodb-replicaset
  • helm repo add stable https://kubernetes-charts.storage.googleapis.com/
  • Modify values.yml file for MongoDB
  • Install MongoDB: helm install debby-staging -f values.yml stable/mongodb-replicaset
  • Connect to MongoDB with admin user: kubectl exec -it debby-staging-mongodb-replicaset-0 -- mongo mydb -u {USER} -p {PWD} --authenticationDatabase admin
  • Expose MongoDB ports: kubectl expose pod debby-staging-mongodb-replicaset-0 --type=LoadBalancer
  • Add micro services port to EC2 load balancer whitelist
  • Upgrade MongoDB: helm upgrade staging-debby -f values.yaml incubator/mongodb-replicaset
  • Delete MongoDB:
    • Get helm list: helm list
    • Delete selected helm chart: helm delete {NAME}
