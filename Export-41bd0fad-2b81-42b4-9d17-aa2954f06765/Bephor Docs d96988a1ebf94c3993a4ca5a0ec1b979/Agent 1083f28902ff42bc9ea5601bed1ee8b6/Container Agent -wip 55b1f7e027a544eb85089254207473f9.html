Container Agent -wip

A typical containerized infra

General Workflow

  1. Agent (John) sends process list on the host
  1. Process service do soft discovery: detect technologies in/out-side of containers
  1. Master topology makes a list of integrations to track with metricbeat tech module if not in container AND List technologies in container
  1. User sends action request to the agent to track metrics (via Minima)
  1. Technology service (Emma) forwards requests
  1. John: If simple beats module (not in container), use dedicated module. Else, if technology in container, add field for both filebeat and metricbeat. Filebeat use docker logs {containerID} for collection.
  1. In the second case, logstash splits docker data appropriately.

Details

1. discovery

  • the container agent (CA) uses docker command docker ps [OPTIONS] to list containers
  • for each container:
    • use sudo docker exec -it test1 ps -eaf to list container processes
    • discover services and processes using two methods, as already implemented in john:

      a. process name-based (soft discovery)

      b. config file-based (hard discovery)

2. data collection

  • once list of technologies identified
  • wait for instructions from Emma (list of target technologies)
  • then, for each target technology:

    2.1. Metrics

we use metricbeat module for docker containers

2.2. Logs

Soft collection

the soft collection is based on listing containers and using filebeat container input to collect STDOUT logs.

Hard collection

  • get the log path contained in the config file
  • copy the log file to a tmp file on the host (or a RAM buffer if possible)
  • instruct filebeat to read the log file from the tmp file path (or the RAM zone)

update: we don't need the tmp file https://www.elastic.co/guide/en/beats/filebeat/current/filebeat-input-docker.html
