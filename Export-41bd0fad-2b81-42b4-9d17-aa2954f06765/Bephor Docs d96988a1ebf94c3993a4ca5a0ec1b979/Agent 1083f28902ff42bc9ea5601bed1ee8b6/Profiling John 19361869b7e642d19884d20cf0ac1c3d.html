Beats profiling

Goal

PacketAI agent, John, relies on Elasticsearch Beats for its log and metric data collection. Below, we want to measure Filebeat and Metricbeat ressource usage given different conditions and data out-throughput.

Experiment Setup

Profiling was done on a MacBook Pro, with a 2.3 GHz 8-Core Intel Core i9 processor, and 16 GB 2400 MHz DDR4. All experiments were performed inside a docker container with debian running. Beats CPU profile is obtained using the --cpuprofile command line option. Beats were outputting to a Kafka pipe, with SSL encryption activated.

Profiling Filebeat

The profiling of Filebeat was based on the HDFS_halfmil.log data which have 713K lines of log, making for 95MB. Filebeat was launched with just this file to output. Its CPU consumption and throughput was obtained under different conditions:

  1. File is directly given as is. Filebeat outputs it as fast as it can.
  1. The logs are streamed even T interval of time to simulate a more realistic situation.

See table below for results:

First profiling of MetricBeat

Conditions: took a docker with the whole ELK stack (Logstash, Elastic and Kibana) installed. Enabled all metricbeat modules. In total, in the output, there are 86 metrics. However, most of them return "not detected" errors. From the ELK stack, there are 12 metrics. In addition, there was a 8 system metrics which are enabled by default. Making for a total of 20 metrics tracked.

CPU usage is 1.83%. 10,3 event/s. Metricbeat run for 29 minutes and produced 26MB data. So, 15600 byte/s.
