#Dashboards

There are 3 steps in creating dashboards:

  1. Create an index-pattern
  1. Create visualizations that use the index-pattern for data (each visualization can have it’s own index-pattern)
  1. Create the dashboard and fill it with the created visualizations

All of the above in Kibana are called saved objects. If a user wants to be able to see a shared dashboard/visualization he needs to have access to its’ saved objects. The saved objects are stored under the .kibana index for the regular Kibana and elasticsearch but in the case of Open Distro which includes multitenancy they are stored under these indexes:

  • .kibana_<hash>_<tenant_name> for tenants
  • .kibana_<hash>_<username> for individual users.

If a user wants to be able to see a dashboard he either has to have it in his own saved objects or in the saved objects of his tenant. By creating the saved objects for the infrastructure tenant and connecting the infrastructure tenant to the infrastructure users (their roles) we enable all of the infrastructure users the ability to see the shared dashboards or visualizations.

All of the infrastructure tenants will have tenant patterns that look like tenant-{infrastructureId}.

The index patterns for the visualizations of the infrastructure tenant will have and index pattern index-{infrastructureId}-* which will basically search for all of the data that will be connected to the tenant in elastisearch.

#Role restrictions

If we want to restrict the users to see only parts of the data in the visualization we do that by assigning them roles with the index patterns restrictions that we want to have. An example would be a user with the marketing role which can see only some indexes inside the infrastructure.

If the marketing role can only see the index-{infrastructureId}-marketing index pattern we create a marketing role and add the restriction to only have acces to that index pattern.

We then connect that role to the infrastructure tenant so it has access to the shared dashboards and add the marketing role to our user.

When the user with the marketing role opens the shared infrastructure tenant dashboard the visualizations in the dashboard will try to access data from the whole index-{infrastructureId}-* pattern.

The security restrictions from the role will only return the data from the index-{infrastructureId}-marketing pattern the user is allowed to see and show the visulizations with the appropriate data.

#Embedding dashboards and visualizations

Dashboards and visualizations are embedded inside Minima thorugh iframes. A typical URL for a shared dashboards looks like:

  • https://kb.packetai.co:5601/app/kibana?security_tenant={tenantName}/dashboard/{dashboardId}?embed=true&_g=()

The parameters that need to be changed when sharing visualizations to users of the same infrastructure are the tenantName which will be set to something like tenant-{infrastructureId} and dashboardId which will be set to something like {infrastructureId}-{dashboardName} for easier sharing.

Other parameters like filters can be added to the URL if needed.

#Creating saved object through the API

The saved objects will be created programatically through the elastisearch API upon the creation of the infrastructure tenant. The objects are stored directly to elasticsearch using the admin user and skipping the Kibana API. A typical endpoint to create an index pattern looks like:

  • https://kb.packetai.co:9200/.kibana_{tenantHashCode}_{tenantName}/_doc/index-pattern:{indexPatternName}

The tenantHashCode is derived from the tenantName with removed special characters such as -with a hashing algorithm(JavaScript implementation).

The indexPatternName needs to be the same as the index pattern we want to target index-{infrastructureId}-*.
