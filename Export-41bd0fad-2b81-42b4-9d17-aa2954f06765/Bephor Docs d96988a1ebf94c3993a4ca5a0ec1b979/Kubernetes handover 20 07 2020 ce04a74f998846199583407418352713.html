We have two kube clusters:

  1. KUBE PROD (3 instances): the production cluster
  1. KUBERNETES (3 instances): contains two environments: dev and staging

To create the cluster use:

eksctl create cluster \

--name bephorprod \

--version 1.16 \

--region eu-west-3 \

--nodegroup-name standard-workers \

--node-type t2.large \

--nodes 3 \

--nodes-min 1 \

--nodes-max 4 \

--ssh-access \

--ssh-public-key /Users/mehdi-packetai/.ssh/id_rsa.pub \

--managed

Mehdi: could build a cluster on ECS instead of EC2 but i don't recommend it at all, because if you don't really know why to scale, it will scale automatically for you

Once the cluster is created, we deploy on the cluster. In gitlab, https://gitlab.packetai.co/monitoring/deployments we have the file https://gitlab.packetai.co/monitoring/deployments/-/blob/master/account-dev.yml to deploy account on the dev cluster.

To connect to a kube cluster:

PREREQUISITES:

AWS CLI

https://eksctl.io/

https://docs.aws.amazon.com/eks/latest/userguide/install-aws-iam-authenticator.html

1. CONFIGURE AWS CREDENTIALS:

location: .aws/credentials

command check: aws configure

2. CHECK ACCESS TO KUBE (knows AWS credentials that have been setup):

aws-iam-authenticator token -i bephor.eu-west-3.eksctl.io

3. UPDATE/CREATE KUBE CONFIG (downladed/generated from AWS if the cluster bephor exists):

aws eks --region eu-west-3 update-kubeconfig --name bephor

4. generate token for access to the dashboard

kubectl -n kube-system describe secret $(kubectl -n kube-system get secret | grep eks-admin | awk '{print $1}')

5. start proxy

kubectl proxy

6. go to

http://localhost:8001/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/#/login
