Role based Access

Grafana

https://grafana.com/docs/grafana/latest/permissions/

Organizations:

  • An organization is a group of users on a Grafana server
  • Each user can belong to more than one organization
  • Every member of the organization has a role in that organization that grants them a certain level of permissions

Teams:

  • A team is a group of users assigned to an organization on a Grafana server
  • Each user can belong to more than one organization and more than one team

Dashboards:

  • A dashboard is a set of one or more panels organized and arranged into one or more rows.
  • Dashboards in Grafana are shared through folder or dashboard permissions assigned to a user account or a team
  • Folders are a way to organize and group dashboards - very useful if you have a lot of dashboards or multiple teams using the same Grafana instance
  • A playlist is a list of dashboards that are displayed in a sequence. You might use a playlist to build situational awareness or to present your metrics to your team or visitors.

Data sources:

  • Grafana supports many different storage backends for your time series data (data source)
  • For each data source there is a permission page that allows you to enable permissions and restrict query permissions to specific users and teams
  • Data source permissions are only available in Grafana Enterprise

Organization roles are:

  • Admin
  • Editor
  • Viewer

Datadog

https://docs.datadoghq.com/account_management/rbac/?tab=datadogapplication

Roles:

  • Three roles by default:
    • Admin - all access
    • Standard - read and edit
    • Read only - read
  • Custom roles is an opt-in Enterprise feature (not sure if they offer fine grained data access or just global permissions for logs, metrics...)

Dashboards:

  • Dashboard can easily be shared to outside users without a Datadog account:
    • Via email
    • By domain
  • Time selectors and template variables can be used to restrict the data shown in the dashboards

ODFE

https://opendistro.github.io/for-elasticsearch-docs/docs/security/access-control/users-roles/

Kibana multi-tenancy

  • Tenants in Kibana are spaces for saving index patterns, visualizations, dashboards, and other Kibana objects
  • Tenants are useful for safely sharing your work with other Kibana users
  • You can control which roles have access to a tenant and whether those roles have read or write access
  • Tenant access is given to user roles and it has 2 options:
    • Read only
    • Read and Write

Roles

  • Roles are the core way of controlling access to your cluster/data
  • Roles contain any combination of cluster-wide permissions, index-specific permissions, document- and field-level security, and tenants
  • Users are mapped to roles in order to get those permissions
  • The users who sign up through Minima are automatically added the admin role which has read and write access to everything (until we offer multitenancy)

Creating a user with dashboard access workflows

ODFE:

  1. A new user is created on Minima/Accounts with access to the new role
  1. Create a dashboard on a new or existing tenant, or use an existing dashboard
  1. Create a specific new role for the new user
  1. Add index permissions to the role which restrict data access
  1. Add tenant permissions to the role so the user has access to the dashboard
  1. Map the user to the created role inside of ODFE

Grafana (video):

  1. Create a new dashboard(or folder)
  1. Create a user and add him to a team/organization
  1. Enable user to have access to the dashboard by adding his team or organization
  1. Enable user to have access to the data source by adding his team or organization

Datadog:

  1. Choose or create a dashboard
  1. Enter emails of (non company) users
  1. Edit Time & Variable Settings to control data access
  1. Datadog will email a magic link to the dashboard to the chosen users

ODFE cons:

  • Access to dashboards and the actual data is separate, dashboards are handled via Kibana multi tenancy and data access via roles
  • All tenant dashboards are saved under a single index which means that the you cannot grant access to individual dashboards/visualizations inside of a tenant
  • The user always has access to all of the dashboards inside of a tenant while Grafana works on adding access per dashboard(folder)
  • If a user has access to multiple tenants he cannot automatically see all of the combined tenants dashboards. The user needs to switch to a tenant through the UI to see the dashboards of that specific tenant

ODFE pros:

  • More fine grained security:
    • Document-level security lets you restrict a role to a subset of documents in an index
    • Field-level security lets you control which document fields a user can see
  • Field masking lets you allow certain roles to see sensitive fields in plain text and mask them for others
  • Specific index access restrictions

Conclusion:

  • Setting up basic user roles and dashboard sharing is more difficult and unintuitive on ODFE than the other two, even when you disregard the Minima user creation requirement
  • It would take more effort for the users to learn how to do it themselves so either we do it for them or add a feature on Minima which would make it easier
  • Datadog dashboard sharing is the easiest and doesn't require account creation
  • Data restrictions on Grafana and Datadog are Enterprise features
  • The ODFE fine grained data access options are a plus but I am not sure if such a functionality is what the users need and it would require ODFE and ELK knowledge to set up
