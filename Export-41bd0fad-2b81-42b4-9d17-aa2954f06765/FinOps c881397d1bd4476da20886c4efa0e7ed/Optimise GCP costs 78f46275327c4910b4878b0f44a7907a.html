Current costs

Target

  • 400eur/month for an atomic cluster
  • beyond that, price should keep proportional to data at ratio:

    (DD price for Kpler - 20% / volume of Kpler data)

Requirements

  • Some of the following actions may require shutting down the prod cluster for up to 1 day
    • must handle ML following cluster shut down
  • We must communicate to clients before such planned maintenance shutdowns

General remarks

  • we are creating too many controllers including statefulsets and deployments → impacts cluster perf (go to kpler → gke → workload → list of controllers per namespace)

Elements to optimise

  • Overall

    As can be seen, ram usage is super high proportional to cpu, across all clusters Note: a few clusters are messed up because most of their pods do not have request .. values

  • Kpler
    • Typical node utilisation
    • cpu is largely underused
    • ram is underused but not too much
    • our algorithms seem to consume a lot of ram but so little cpu

    • OD-system consumes 4 nodes

    • Since kpler has many topics , and each topic translates into MAD/LAD pods → RAM consumption is super high (and super high compared to cpu)
  • Metron

    not pods don’t have requests and limits

    • od-system → opendistro-opendistro-es-data has 3 pods, each takes a whole instance (8vcpu and 30G ram)

Plan

Note: order is important

General

  • Staging is in 3 AZs
  • except Cleyrop, all other clusters still have kafka < - > cluster over the NAT → expensive
  • correct the creation of controllers (see general remarks above)

Optimise resource allocation

  • set ram request to usage+20% → would reduce costs by 50% across all clusters
    • apply custom VPA to argo-event
    • adjust requests to usage for all other pods
  • metron kafka is used 10% and plezi is 2% - but live downsize is not possible (there are ways though to be explored)

Optimise resource types

  • adopt spot instances

    We put 50% nodes on spot, without filtering MAD/AM

Optimise resource usage (big focus on RAM)

  • optimise ES → will reduce 20-30% of costs, dependant on cluster (note: execution should pay attention to template indexer work this). (it consumes 38.4G ram on Kpler)
  • optimise usage of persistent volumes

    Current costs - Balanced capacity PD costs

    Plezi: 560eur per month

    Kpler: 870eur per month

    Metron: 470eur per month

    • MAD pods are created with 1G persistent disk - never used
    • ES pods for data (-es-data) are using 3 replicas → reduce to 2
    • install ops agent on all kafka instances to monitor usage
    • create an auto action based on disk usage to scale persistent volume capacity
    • can we start disks and PVs at 1G then scale according to usage (including for kafka and ES)?
  • optimise LAD (it consumes 13.25G ram on Kpler, 50G on Metron)
  • optimise MAD (it consumes <13G on Kpler)
